# T-12.6 — Replay HUD follows the scrubber

## Goal

During replay of a finished run the canvas already shows the scrubbed tick: `scrubTo` repoints `latestFrame`, and `ComponentNode`/`FlowEdge` read it. The HUD cards don't follow, because they read `aggregates`, which is folded once per streamed frame and stays frozen at the end of the run. This task makes the HUD's "current" numbers (p95, errors, served, lag, bottleneck) come from the displayed frame. Whole-run peaks still come from the fold. It also adds a single named seam, `selectDisplayFrame`, which every HUD reader of "the frame being shown" uses. That includes T-12.5's p95 popover.

**Accept:** While scrubbing a finished run, the HUD cards show the scrubbed frame's values (p95, errors, served, lag, bottleneck), matching the canvas. Releasing to the end shows the end-of-run values. "peak" subs keep showing the whole-run peak.

**The seam (for reconciling with T-12.5):**
- `selectDisplayFrame(s)` returns `s.latestFrame`. This is already the scrubbed frame during replay (`scrubTo` sets it) and the newest frame while running. Any HUD element that reads "the current frame" uses `useSimStore(selectDisplayFrame)`. That covers T-12.5's top-3 tail-contributor popover and the cards. Nothing reads `frames[frames.length - 1]`, `frames.at(-1)` or `result.frames` to mean "now".
- `displayAggregates(agg, frame, nodeOrder)` is the HUD's view. It takes the scalars from the displayed frame and the peaks and cumulative values from the whole-run fold.

Calls made (lead to review):
1. **`asyncLost` stays whole-run** while scrubbing. It renders in the Lag card's sub next to `peak …`, and the Accept says subs show whole-run values. Only `maxLagSec` (the card value) follows the scrub.
2. **No store-shape change.** The display view is computed in `useRunControls` on each render from `aggregates`, `latestFrame` and `runGraph`. It is not stored as a new field. A zustand selector that returns a fresh object would loop `useSyncExternalStore`, so the overlay is computed outside the selector. The cost is one pass over the nodes per render.
3. **`ReplayScrubber.tsx` needs no change.** It already drives `scrubTo`, and its "Releasing to the end" path (`scrubTo(last)`) already makes `latestFrame === frames[last]`. At that frame `displayAggregates` returns exactly the folded values (unit-tested below). This is a deviation from the task's Files list. Nothing gets added to the scrubber.
4. No HUD "replay" badge is added. The scrubber's `12.3s / 30.0s` readout already says which moment is shown.

Behaviour that stays the same: while `running` or `paused`, `latestFrame` is the newest frame, so `displayAggregates` gives values identical to `aggregates`. When idle, `latestFrame` is null and the fold is returned unchanged. `chaos` keeps using `aggregates.elapsedSec`, which is untouched.

## Steps

### 1. `app/src/stores/sim-store.ts`: extract the bottleneck pick and add the display view

Add the pure helper below directly above `foldAggregates`, and make `foldAggregates` use it. Behaviour stays the same: ties go to the first node in `nodeOrder`, and with no nodes the result is `null`/`0`.

```ts
/** Pure: highest-util node in a frame; ties broken by `nodeOrder`; none → null/0. */
export function bottleneckOf(
  frame: SimFrame,
  nodeOrder: readonly string[],
): { nodeId: string | null; util: number } {
  let nodeId: string | null = null;
  let util = -1;
  for (const id of nodeOrder) {
    const u = frame.perNode[id]?.util ?? 0;
    if (u > util) {
      util = u;
      nodeId = id;
    }
  }
  return { nodeId, util: util < 0 ? 0 : util };
}
```

In `foldAggregates`, delete the local loop and write:
```ts
const bottleneck = bottleneckOf(frame, nodeOrder);
// ...
bottleneckNodeId: bottleneck.nodeId,
bottleneckUtil: bottleneck.util,
```

Directly below `foldAggregates`, add:

```ts
/**
 * Pure: the HUD's view of a run. The "now" scalars (p95, errors, served, lag,
 * bottleneck, elapsed) come from the displayed frame: the scrubbed one during
 * replay, else the newest. Peaks and the cumulative async loss stay whole-run.
 * With no frame (idle) the fold is returned as-is.
 */
export function displayAggregates(
  agg: SimAggregates,
  frame: SimFrame | null,
  nodeOrder: readonly string[],
): SimAggregates {
  if (frame === null) return agg;
  const bottleneck = bottleneckOf(frame, nodeOrder);
  return {
    ...agg,
    elapsedSec: frame.t,
    p95Ms: frame.p95Ms,
    errorRate: frame.errorRate,
    servedRps: frame.servedRps,
    // run files exported before M8 have frames without this field
    maxLagSec: frame.maxLagSec ?? 0,
    bottleneckNodeId: bottleneck.nodeId,
    bottleneckUtil: bottleneck.util,
  };
}

/**
 * The frame the canvas and HUD show: the scrubbed frame during replay
 * (`scrubTo` repoints `latestFrame`), else the newest one; null before a run.
 * HUD readers of "the current frame" (cards, the p95 popover) use this.
 */
export const selectDisplayFrame = (s: {
  latestFrame: SimFrame | null;
}): SimFrame | null => s.latestFrame;
```

Update the `latestFrame` doc comment in `interface SimStore` to read `/** the frame on screen: newest while running, the scrubbed one during replay (see selectDisplayFrame); null before a run */`.

it("the HUD view follows the scrubbed frame and keeps whole-run peaks", () => {

  vi.advanceTimersByTime(2000);
