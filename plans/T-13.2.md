# T-13.2 — Clickable steps and the board slot

## Goal

The Practice phase bar's step chips become buttons. The phase store gains a UI-only **viewed step** that is separate from the clock's step. The center area of `PracticeWorkspace` shows a board for the viewed step when that step is Requirements, Entities or API, and the simulation canvas otherwise. Clicking an earlier chip only changes the view. Clicking a later chip moves the clock like Skip does. The clock never changes the view: when a timer runs out, the view stays where it is and a "Go to X" nudge appears. While a board is shown, the palette and node inspector hide, and the metrics bar, verdict, replay scrubber and any running test stay live. The three boards are placeholders in a new `StepBoard` switch. T-13.3, T-13.4 and T-13.5 each swap one case for their real component. A right-column slot (`StepAside`) lets T-13.5 add the entity-name list on the API step. `PhaseNotes` follows the viewed step.

**Accept (verbatim):**
- Step chips are buttons with clear done / current / viewed states.
- Clicking an earlier step views its board and the clock keeps running on the current step (spec, user call). Clicking a later step jumps the clock there like Skip and starts its timer. Clicking the current step returns the view to it.
- While the view is behind the clock, a chip shows the way back with the current step's live time ("← Back to API · 03:10" style).
- When a timer runs out, the clock advances but the view stays on the board being used. The phase bar highlights the new current step and shows a "Go to Entities →" style nudge. The view never changes because of the clock (spec, user call). This also holds while viewing an earlier step when a boundary passes.
- Before High-level design the center shows the current or viewed step's board instead of the locked canvas. In HLD and Deep dives the center shows the canvas, unless an earlier board is being viewed. Then only the canvas spot is replaced: the metrics bar, verdict and replay scrubber stay visible, a running test keeps running, and the palette and node config panel hide and come back on return (spec, user call).
- The viewed step isn't persisted. A reload opens on the clock's step.
- e2e covers: jumping back keeps the clock counting; a timeout while typing in a board keeps focus and text (review focus 1, via a short phase budget or a test hook the planner picks); reload while viewing an earlier step (review focus 2).
- Screenshots: each step, the back chip, the timeout nudge, an HLD view of an earlier board during a run.

**Design calls (planner, for lead review):**
- **The view is an explicit `viewedPhase: Phase` and never `null`.** A `null` value meaning "follow the clock" would let a timeout move the view, which the spec forbids. Only `goToStep`, `skip`, `attach` and `reset` set it. `tick` never does.
- **Skip moves the view to the new current step** and clears the nudge. Skip is a user click that means "I'm moving on". If the view stayed put, pressing Skip would only change the chip colour.
- **Clicking a later chip** sets `phase` and `viewedPhase` to the target with the target's full budget. It leaves `running` alone, exactly like `skip` (paused stays paused). "Starts its timer" is read as "its countdown starts from its full budget". Jumping several steps records one `phase_started` (the existing design-store subscriber fires on the `phase` change).
- **Back chip vs. nudge.** A new `autoAdvanced: boolean` is set by `tick` when the clock crosses a boundary on its own, and cleared by every view change. Whenever `viewedPhase !== phase`, the bar shows one return chip. With `autoAdvanced` it's the amber nudge **"Go to Entities →"**, and the current chip gets an amber ring. Otherwise it's **"← Back to API · 03:10"**, using the live `remainingSec`. If the user goes back manually and a boundary then passes, the label switches to the nudge (Accept: "this also holds while viewing an earlier step"). The arrows are lucide icons, so the accessible names are `Go to Entities` and `Back to API · 03:10`.
- **Chip states:** done chips show a `Check` icon instead of their number. The current chip keeps the sky style and `aria-current="step"` (existing e2e selectors rely on it). The viewed chip, when it isn't the current one, gets a neutral ring, brighter text and an `Eye` icon. Every chip has `aria-pressed={viewed}` and `aria-label="<Label> step"`.
- **Which steps have a board:** `hasStepBoard(phase)` is true for the steps before `CANVAS_UNLOCK_PHASE` (requirements, entities, api). The center shows `StepBoard` when `hasStepBoard(viewedPhase)` holds, and `DesignCanvas` otherwise. This covers "before HLD" (the view is always ≤ the clock) and "an earlier board in HLD or Deep dives" with one rule. Viewing HLD while the clock is on Deep dives shows the canvas, and the notes switch to the HLD note.
- **Verdict and scrubber keep their tree position** in both modes, so `ReplayScrubber`'s local `playing` state survives a swap. Only the wrapper classes change. In canvas mode they're absolute overlays as today. In board mode they're in-flow rows above and below the board, so they never cover board content. `empty:hidden` collapses those rows when the component renders `null`. `DesignCanvas` unmounts while a board is shown, and `fitView` runs again on return. Nothing about the run lives in the canvas (sim-store plus worker), so a run keeps going. Palette and `NodeConfigPanel` are conditionally rendered. Both are stateless or store-backed, so they "come back on return". Selection stays in design-store.
- **e2e timeout:** Playwright's `page.clock` (`install()` before `goto`, then `runFor(...)` to fire the 1 Hz interval). There's no test hook in app code.
- **Notes follow the view.** `PhaseNotes` edits `phaseNotes[viewedPhase]`, so typing across a timeout keeps writing into the same step's note. The T-4.2 requirements seeding effect keeps keying on the **clock** phase, as today, so behaviour doesn't change. T-13.3 deletes that effect anyway.
- **Consequences to know about:** (a) Before HLD the canvas isn't visible at all, so an imported or old Practice design opened on a fresh clock shows the Requirements board until the user moves to HLD, as the spec intends. `smoke.spec.ts` therefore seeds a High-level design clock. (b) Dropping a design file only works on the canvas (T-12.8). On a board, the ⋯ menu's Import is the way in. (c) `DesignCanvas`'s lock banner is now unreachable in Practice: the canvas only renders once the view, and so the clock, is at HLD or later. It's left untouched as a guard, and there's no behaviour change in Quick, which passes `lockable={false}`.

     ```ts
     /** Steps before High-level design each get a center board (M13). `BoardPhase` is the core type from T-13.1 (`import type { BoardPhase } from "@/lib/core"`); do not redefine it. */
     export function hasStepBoard(phase: Phase): phase is BoardPhase {
       return phaseIndex(phase) < phaseIndex(CANVAS_UNLOCK_PHASE);
     }

     /** What the phase bar's return chip shows while the view is behind the clock (T-13.2). */
     export type ViewReturn = { kind: "back" | "nudge"; phase: Phase } | null;
     export function viewReturn(s: {
       phase: Phase;
       viewedPhase: Phase;
       autoAdvanced: boolean;
     }): ViewReturn {
       if (s.viewedPhase === s.phase) return null;
       return { kind: s.autoAdvanced ? "nudge" : "back", phase: s.phase };
     }
     ```
   - Add these to `interface PhaseStore` (after `running`):
     ```ts
     /** Step whose board/notes are shown (T-13.2). UI-only: never persisted; only clicks, skip, attach and reset change it — never the clock. */
     viewedPhase: Phase;
     /** True once the clock crossed a step boundary on its own since the view was last chosen (drives the "Go to …" nudge). */
     autoAdvanced: boolean;
     /** Chip click: earlier/current step → view it (clock untouched); later step → jump the clock there with its full budget (like skip) and view it. */
     goToStep: (phase: Phase) => void;
     ```
