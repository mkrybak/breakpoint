# T-7.1 — Browser smoke test (plan)

## Goal

A single Playwright test drives the real production build in Chromium through the path no automated test covers today: landing page → saved design → Run → live sim (worker) → HUD. It runs locally with `npm run e2e`, and CI runs it after `build`.

Acceptance criteria (verbatim from `tasks/M7-quick-mode.md`):

> One Playwright test: open landing → open a design built from `examples/twitter.json` → press Run → a verdict appears and at least one node changes state. `npm run e2e` runs it locally, and CI runs it after `build`. `@playwright/test` (dev-only) gets a dependency-budget entry in [[05-engines]]. Lands first because M7 reshuffles the UI and nothing automated covers canvas → worker → HUD today.

## Context

Read first:

- `app/src/components/landing/LandingScreen.tsx`: the saved-designs list renders each design as `<Link href="/design/{id}">{name}</Link>`, read from localStorage via `listDesigns()`.
- `app/src/persistence/local.ts`: `DesignRecord` shape; localStorage key `bp:design:<id>`. `parseDesignRecord` is forgiving: `phaseNotes`, `actionLog` and `scenarioId` may be omitted.
- `app/src/components/hud/MetricsBar.tsx`: the Run button (accessible name exactly `Run`; `Re-run` after a run; `Stop` while running).
- `app/src/components/hud/Verdict.tsx` + `hud-format.ts` (`describeRunStatus`): after a run the verdict label is exactly `Passed` or `Failed`.
- `app/src/components/hud/EventLog.tsx`: each log line renders `entry.message` in its own `<span>`.
- `app/src/stores/scenario-store.ts`: the default scenario is `SCENARIO_PRESETS[0]` = Black Friday (5000 RPS base, 60s).

**Why the fixture modifies twitter.json.** Under Black Friday, the stock `examples/twitter.json` (app fleet = 8 replicas = 32k RPS) changes no node state until t=45s, too slow for a smoke test. The test therefore builds its design from `examples/twitter.json` with the `app` node's `replicas` set to **1** (4k RPS < 5k offered). Verified with the sim CLI: at t=0 the event `App fleet overloaded at 4k RPS — shedding load` fires immediately. The test observes "a node changes state" through that event-log line, which needs no app-code change.

**Why Stop.** The run is 60s of real time. The test presses Stop once the state change is seen; `stop` makes the worker post `done` with a verdict over the frames so far (`sim-store.ts`), so the verdict appears within a second. Depending on timing, a stopped run can be `Passed` or `Failed` (the error-rate criterion only applies from t ≥ 3s), so the test accepts either label.

Engine rules: this task adds no code under `src/`. Nothing in `e2e/` imports from `src/`; it imports only `@playwright/test` and the JSON example. `.dependency-cruiser.cjs` is untouched (depcruise scans `src tests scripts`, not `e2e`). Vitest only collects `tests/**/*.test.ts` and `src/**/*.test.ts`, so `e2e/*.spec.ts` stays out of `npm test`.

Expected deviation from the task's Files list: `.gitignore`, `eslint.config.mjs`, `app/README.md`, `05-engines.md` and `01-architecture.md` are also edited (ignore Playwright output, docs). Note this under the task when ticking it.

## Steps

### 1. Install the dependency

In `app/`:

```bash
npm install --save-dev @playwright/test@^1.65.0
npx playwright install chromium
```

`package.json` `devDependencies` gains `"@playwright/test": "^1.65.0"`, and `package-lock.json` updates. Do not add `playwright` (the bare package) or any other dependency.

Arch Linux note: `playwright install` may warn that the OS is not officially supported and download the Ubuntu fallback build; that is fine. If Chromium then fails to *launch* in Verification, stop and return `STATUS: BLOCKED` with the error. Do not switch to a system browser or change the config.

### 2. Add the script

`app/package.json` `scripts`: add after `"test"`:

```json
"e2e": "playwright test",
```

### 3. Create `app/playwright.config.ts`

```ts
import { defineConfig, devices } from "@playwright/test";

const PORT = 3100;
const isCI = !!process.env.CI;

/**
 * Browser smoke tests (T-7.1) against the production build. CI has already
 * run `npm run build` in an earlier step, so it only starts the server;
 * locally the web server builds first so `npm run e2e` works from scratch.
 */
export default defineConfig({
  testDir: "./e2e",
  fullyParallel: false,
  workers: 1,
  forbidOnly: isCI,
  retries: isCI ? 1 : 0,
  reporter: isCI ? [["github"], ["html", { open: "never" }]] : [["list"]],
  use: {
    baseURL: `http://localhost:${PORT}`,
    trace: "retain-on-failure",
  },
  projects: [
    {
      name: "chromium",
      use: { ...devices["Desktop Chrome"], viewport: { width: 1440, height: 900 } },
    },
  ],
  webServer: {
    command: isCI
      ? `npm run start -- -p ${PORT}`
      : `npm run build && npm run start -- -p ${PORT}`,
    url: `http://localhost:${PORT}`,
    reuseExistingServer: !isCI,
    timeout: 180_000,
  },
});
```

Port 3100 avoids colliding with `npm run dev` on 3000.

### 4. Create `app/e2e/smoke.spec.ts`

```ts
import { expect, test } from "@playwright/test";
import twitter from "../examples/twitter.json";

const DESIGN_ID = "e2e-twitter";
const DESIGN_NAME = "E2E Twitter";

/**
 * examples/twitter.json with the app fleet cut to 1 replica (4k RPS cap):
 * Black Friday's 5k RPS base overloads it on the first tick, so a node
 * changes state immediately instead of at t=45s.
 */
function buildRecord() {
  const graph = structuredClone(twitter);
  const app = graph.nodes.find((n) => n.id === "app");
  if (!app) throw new Error("examples/twitter.json has no 'app' node");
  app.config = { ...app.config, replicas: 1 };
  return {
    id: DESIGN_ID,
    name: DESIGN_NAME,
    scenarioId: "",
    graph,
    updatedAt: new Date().toISOString(),
  };
}

test("landing → design → run → live state change → verdict", async ({ page }) => {
  const record = buildRecord();
  await page.addInitScript(
    ({ key, value }) => window.localStorage.setItem(key, value),
    { key: `bp:design:${DESIGN_ID}`, value: JSON.stringify(record) },
  );

  await page.goto("/");
  await page.getByRole("link", { name: DESIGN_NAME, exact: true }).click();
  await expect(page).toHaveURL(new RegExp(`/design/${DESIGN_ID}$`));

  // the canvas rendered the seeded graph
  await expect(page.getByText("App fleet", { exact: true }).first()).toBeVisible();

  await page.getByRole("button", { name: "Run", exact: true }).click();

  // a node changed state: the worker streamed frames and the event log shows it
  await expect(page.getByText(/App fleet overloaded/).first()).toBeVisible({
    timeout: 15_000,
  });

  await page.getByRole("button", { name: "Stop", exact: true }).click();

  // a verdict appeared
  await expect(page.getByText(/^(Passed|Failed)$/)).toBeVisible({ timeout: 10_000 });
  await expect(page.getByRole("button", { name: "Re-run", exact: true })).toBeVisible();
});
```

If `structuredClone(twitter)` doesn't typecheck because `app.config` is inferred as `{}` or a narrow JSON type, change only the clone line to `const graph = structuredClone(twitter) as { nodes: { id: string; config: Record<string, unknown> }[] } & typeof twitter;`. Do not change the test logic.

### 6. CI: run it after build

`.github/workflows/ci.yml` (repo root): after the `Build` step, append:

```yaml
      - name: Install Playwright browser
        run: npx playwright install --with-deps chromium

      - name: E2E smoke test (Playwright)
        run: npm run e2e

      - name: Upload Playwright report
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: playwright-report
          path: |
            app/playwright-report
            app/test-results
          retention-days: 7
```

GitHub Actions sets `CI=true`, so the config only starts the already-built server.
