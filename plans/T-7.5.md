# T-7.5 — Quick mode workspace layout (plan)

## Goal

`/design/[id]` picks its layout from the attached design's mode. Quick designs get a smaller, simpler workspace: palette, canvas, node config, a big Run button, a three-number HUD, a plain-language verdict, the event log and the replay scrubber. Scenario choice sits behind a "More scenarios" menu and live chaos behind a "Break it" menu. Practice designs render exactly as they do today. Interview designs (not built until M11) open in the Practice layout with a one-line notice. Quick records no actions and never locks the canvas.

Accept (verbatim from `tasks/M7-quick-mode.md`):

> `/design/[id]` renders by mode. Quick has no phase bar, phase notes, requirements panel, review link or canvas lock, and no action recording. The HUD is simplified to served RPS, p95 and error %, and the verdict uses plain language. Run is the visually dominant action. Scenario choice sits behind "More scenarios" and chaos behind "Break it"; both are hidden, not disabled. Practice renders exactly as today. Run via `/ui`.

Calls made (lead, please review):
1. **The mode is read from the store, not the server.** localStorage is client-only, so `page.tsx` renders a client `DesignWorkspace`. That component attaches the design and renders nothing (a blank `bg-neutral-950` screen) until `designId === id`, so there's no flash of the wrong layout. Side effect: Practice's server HTML is now blank for one frame. After hydration, Practice is pixel-identical.
2. **`attachDesign` moves from `NodeConfigPanel` to `DesignWorkspace`.** Leaving it in both would re-attach on every open, and the second attach would autosave and bump `updatedAt`. NodeConfigPanel's rendered output doesn't change.
3. **Layouts are a `Record<DesignMode, Component>` map** (the registry-map pattern), so M11 adds the Interview layout by replacing one entry.
4. **Quick scenario lifecycle.** On entering Quick: the sim resets and the scenario becomes a clone of `STARTER_SCENARIO`. This uses `useLayoutEffect`, so the first paint never shows Practice's Black Friday. On leaving Quick: the sim resets and the scenario goes back to `SCENARIO_PRESETS[0]`, so nothing leaks into Practice. Picking a scenario from "More scenarios" also resets the sim, because the old verdict was for a different scenario. The selection is not persisted: reopening a Quick design starts on the starter again.
5. **"Hidden, not disabled".** "More scenarios" is always shown (a closed menu). "Break it" is only rendered while a run is live (`running`/`paused`), because chaos does nothing otherwise. Its items are filtered to the running graph: "Kill an app server" needs an `app_server`, "Flush the cache" needs a `cache`, and the spike always applies.
6. **The plain verdict** keeps the exact headline `Passed`/`Failed` (e2e-stable), adds one sentence per failure or one success sentence, and hides advisories (they're grader hints).
7. **No action recording** is enforced in one place: `recordInterviewAction` returns early when `designMode === "quick"`. That covers graph edits, phase changes, runs and chaos.
8. **The Quick right column** = a read-only scenario summary (name, description, one-line goal), two marked slots for T-7.6/T-7.7, then the event log. NodeConfigPanel (node config + design Export/Import JSON) stays the same as in Practice. There's no review link, so there's no run-bundle export.

5. **`app/src/components/hud/hud-format.ts`**: add the pure helpers (import `Scenario, Verdict, VerdictFailure` from `@/lib/core`):
   ```ts
   /** Budget rate 0–1 → "1%", "0.5%" (no trailing zeros). */
   export function formatBudgetPct(rate: number): string { return `${Number((rate * 100).toFixed(2))}%`; }
   /** Sim seconds → "12.3s" ("4s", not "4.0s"). */
   export function formatSec(t: number): string { return `${Number(t.toFixed(1))}s`; }

   /** Quick mode's read-only goal line, e.g. "Keep p95 under 200 ms and errors under 1%." */
   export function describeScenarioGoal(scenario: Scenario): string {
     let goal = `Keep p95 under ${scenario.pass.p95Ms} ms and errors under ${formatBudgetPct(scenario.pass.maxErrorRate)}`;
     if ((scenario.pass.minSurvivedKills ?? 0) >= 1) goal += ", even when a server goes down";
     if (scenario.pass.consistency === "strong") goal += ", with strongly consistent reads";
     return `${goal}.`;
   }

   const PLAIN_FAILURE: Record<string, (f: VerdictFailure, s: Scenario) => string> = {
     p95: (f, s) => `Responses got too slow: p95 stayed above ${s.pass.p95Ms} ms for too long, starting at ${formatSec(f.atSec)}.`,
     "error-rate": (f, s) => `Too many requests failed: errors went over ${formatBudgetPct(s.pass.maxErrorRate)} at ${formatSec(f.atSec)}.`,
     "kill-survival": (f, s) => `Losing a server hurt users: errors went over ${formatBudgetPct(s.pass.maxErrorRate)} at ${formatSec(f.atSec)}, right after it went down.`,
     consistency: () => "Some reads can return stale data, but this scenario needs strong consistency.",
   };

   export const PLAIN_CAPACITY_TIP =
     "Look at the canvas: red nodes ran out of capacity, grey ones went down. Select a node to change its settings.";

   /**
    * Quick mode's plain-language verdict lines (the headline stays describeRunStatus's
    * "Passed"/"Failed"). Unknown criteria fall back to the engine's detail string.
    * Advisories are omitted: they're grader hints.
    */
   export function describeVerdictPlainly(verdict: Verdict, scenario: Scenario): string[] {
     if (verdict.passed) {
       return [`Your design handled “${scenario.name}”: p95 stayed under ${scenario.pass.p95Ms} ms and errors under ${formatBudgetPct(scenario.pass.maxErrorRate)}.`];
     }
     const lines = verdict.failures.map((f) => PLAIN_FAILURE[f.criterion]?.(f, scenario) ?? f.detail);
     if (verdict.failures.some((f) => f.criterion !== "consistency")) lines.push(PLAIN_CAPACITY_TIP);
     return [...new Set(lines)];
   }
   ```
