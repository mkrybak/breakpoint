# T-12.7 — Small polish (panel input focus ring + Practice phase survives reload)

## Goal

Two small fixes. First, right-panel form inputs get a visible focus ring and a 32px minimum height. Second, the Practice interview clock (phase, countdown, elapsed time, paused/running) is saved per design in localStorage and restored when the design opens. A reload during High-level design then keeps the canvas unlocked, and the action log keeps counting time from where it was instead of restarting at 0.

**Accept (verbatim):** Panel inputs (`INPUT`) get a visible focus ring and a 32px min height. The Practice phase survives a reload: the canvas isn't re-locked behind "High-level design" after a refresh.

Calls made (lead, please review):
1. **Per design, separate key.** The clock is stored under `bp:phase:<designId>` as `{ phase, remainingSec, elapsedSec, running }`. It isn't added to `DesignRecord`: autosave/export of the record stays as it is, and the record's autosave only fires on graph/notes/log edits. `deleteDesign` also removes the key, like the scorecard.
2. **Time while closed doesn't count.** On restore the clock resumes from the saved `remainingSec` with the saved `running` flag. A running clock keeps running after the reload; a paused one stays paused. No wall-clock catch-up.
3. **Attach/detach lifecycle.** `PhaseBar` attaches the clock to the design on mount (`useLayoutEffect`, so the canvas never paints locked for a frame) and detaches on unmount. While detached nothing is saved, so the existing `usePhaseStore.getState().reset()` calls in `LandingScreen`/`TryPracticeLink` (made while the previous design is still "attached" in the design store) can't overwrite the previous design's saved clock. Those reset calls stay; they're now redundant but harmless (attaching a design with no saved clock gives a fresh one).
4. **Recording guard (fixes a latent bug).** `phase_started` is recorded only when the clock belongs to the design store's attached design and the transition isn't the attach itself. Without the guard, restoring HLD on attach would log a spurious "entered hld". The guard also stops a bug that exists today: the landing's `reset()` appends "entered requirements" to the previously opened Practice design's log, because the design store never detaches.
5. **Duplicated panel styles.** `RequirementsPanel` and `ScenarioPanel` switch to the shared `FIELD_LABEL`/`INPUT`, so every right-panel input gets the ring. `HEADING` stays local (not part of this task).
6. **Ring style.** `focus:` rather than `focus-visible:`. Chrome doesn't match `:focus-visible` on a mouse-focused `<select>`, and the ring should show wherever typing goes. This matches the landing `INPUT`, which uses `focus:`. `outline-hidden` (Tailwind v4) keeps a forced-colors outline.

5. **`app/src/stores/phase-store.ts`.**
   - Import `loadPhaseClock, savePhaseClock, type PhaseClock` from `@/persistence/phase-clock`.
   - Add to `PhaseStore`:
     ```ts
     /** Design this clock belongs to and persists under (T-12.7); null = detached, nothing saved. */
     designId: string | null;
     /** Bind to `id`: restore its saved clock, or start a fresh one. Does not write. */
     attach: (id: string) => void;
     /** Stop persisting. Clock values are kept. */
     detach: () => void;
     ```
   - Add a module helper (place it after `const FIRST`):
     ```ts
     function freshClock(): PhaseClock {
       return { phase: FIRST.phase, remainingSec: FIRST.durationSec, elapsedSec: 0, running: true };
     }
     ```
   - Store: the initial state becomes `...freshClock(), designId: null,`. `reset: () => set(freshClock())` keeps `designId`. Add:
     ```ts
     attach: (id) => set({ designId: id, ...(loadPhaseClock(id) ?? freshClock()) }),
     detach: () => set({ designId: null }),
     ```
     The `attach` must stay a single `set`, so subscribers see the id change and the restored phase in one update (step 7 relies on this).
   - After the store, add the persistence subscription:
     ```ts
     // Persist the attached design's clock on every change (≈1 write/s while running;
     // ~80 bytes). Attach/detach transitions are not edits: skipping them avoids
     // echo-saving a just-loaded clock.
     usePhaseStore.subscribe((state, prev) => {
       if (state.designId === null || state.designId !== prev.designId) return;
       if (
         state.phase === prev.phase &&
         state.remainingSec === prev.remainingSec &&
         state.elapsedSec === prev.elapsedSec &&
         state.running === prev.running
       ) return;
       savePhaseClock(state.designId, {
         phase: state.phase,
         remainingSec: state.remainingSec,
         elapsedSec: state.elapsedSec,
         running: state.running,
       });
     });
     ```
