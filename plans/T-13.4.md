# T-13.4 — Entities board

## Goal

Replace the Entities step's placeholder in T-13.2's `StepBoard` with a real entity board. It is a second, separate React Flow instance with the dotted background, pan and zoom. Each node is an entity box with a name header and a field list (name and free-text type). Lines between boxes are relations, and their ends are drawn in crow's-foot notation (a bar for one, a foot for many) with no text. Clicking a line opens a picker of the four kinds drawn as icons. All edits go through T-13.1's design-store board actions. A `readOnly` mode renders a passed-in board with no store access, for T-13.6's review screen.

**Accept (verbatim):**
- A separate React Flow instance (not the simulation canvas) with the same dotted background, pan and zoom.
- "+ Entity" adds a box at a free spot and focuses its name. A box has a name header and a list of fields (name + free-text type). Enter in a field adds the next one. Fields can be deleted and reordered.
- Boxes drag; positions are saved. Boxes can be deleted.
- Deleting a box deletes its relations (review focus 3, unit test on the store action).
- Dragging from one box to another creates a relation, defaulting to one-to-many.
- Line ends show the type in crow's-foot notation (a bar for one, a foot for many), with no text on the line (spec, user call). Clicking a line opens a picker of the four types drawn as icons. Lines can be deleted.
- Self-relations and re-pointing a line's end are the planner's call (log it).
- Screenshots: the demo's User / Order / Product board with an open picker, at 1440×900 and 1280×800.

**Planner calls (log in Decisions, step 9):**
1. **Self-relations are allowed** (User follows User, Employee manages Employee, Category parent). React Flow's strict connection mode already accepts a box's right dot → its own left dot. The store allows them. The line is drawn as an orthogonal loop: out of the right side, over the top of the box, into the left side. It gets the same crow's-foot ends, and the picker sits at the top of the loop.
2. **Re-pointing is allowed:** drag a line's end onto another box (React Flow reconnect, `onReconnect` → `repointRelation`). The kind is kept. Dropping on empty space or onto a pair that is already related leaves the line as it was.
3. **Fixed handles:** each box has a target dot on its left and a source dot on its right. Lines are always stored from → to, so the kind reads in the drawn direction. A connection to a pair that is already related is refused while dragging (`isValidConnection`), so the user sees it doesn't snap.
4. **Field types are free text with suggestions:** a native `<datalist>` (uuid, string, text, int, bigint, float, decimal, bool, timestamp, date, enum, json). This costs no dependency.
5. **Box inputs read the store directly, not node data.** React Flow pushes controlled `nodes` into its internal store in a `useEffect`, which is asynchronous. A controlled input fed only by node data would be reset by React and lose its caret on every keystroke. The editor subscribes to `useDesignStore` for its own entity, so the value updates in the same render. Node ids are the entity ids, `nodeTypes`/`edgeTypes` are module constants, and every input and button carries `nodrag`.
6. **"+ Entity" placement:** a grid scan of the visible viewport (224 px columns, 152 px rows, 24 px padding, 32 px gap), using the first cell that doesn't overlap any box at its measured size. If nothing is free, the box goes to the right of every box and the view pans to it (`setCenter`). Positions are rounded to whole pixels.
7. **The toolbar sits above the flow** (a bar with "+ Entity" and a one-line hint), not as a React Flow `Panel`, so new boxes at the top-left are never hidden under it. The viewport isn't persisted: `fitView` (maxZoom 1) runs on each mount.
8. **Field keyboard:**
   - Enter in a field's name or type adds an empty field below and focuses its name.
   - Enter in the entity name focuses the first field, or adds one if the box has none.
   - Backspace in an empty field (name and type both empty) deletes it and focuses the previous field's name, or the entity name.
   - Alt+↑/↓ reorders.
   - A grip on each field row drags it within its own box (native HTML5 DnD, the same pattern as T-13.3).
9. **Picker behaviour:**
   - It opens on line click (`onEdgeClick`), or when a line is selected from the keyboard (React Flow selects a focused edge on Enter).
   - Choosing a kind applies it and closes the picker. Escape, a pane click or selecting something else also closes it.
   - The picker also holds "Delete relationship". The Delete/Backspace key on a selected line deletes it too.
   - The selected line is drawn sky blue.
10. Boxes are deleted with a trash button in the header, or Delete/Backspace while the box is selected. Both go through `removeEntity`, so relations cascade.

   Body: `const { focus } = useEntityBoardUi(); const ref = useRef<T>(null); useLayoutEffect(() => { if (focus?.key !== key) return; let tries = 0, frame = 0; const attempt = () => { const el = ref.current; if (el) { el.focus({ preventScroll: true }); if (document.activeElement === el) return; } if (++tries < 30) frame = requestAnimationFrame(attempt); }; attempt(); return () => cancelAnimationFrame(frame); }, [focus, key]); return ref;`.
