# T-7.6 — Challenges + next-challenge nudge

## Goal

Give Quick mode a next step after the first green run. Four challenges are added as plain data, each one a Quick-only scenario plus a one-line goal and a hint. After a run, a small card in the Quick workspace suggests the next unsolved challenge. Picking it switches the scenario. The same card lists all four challenges with solved marks. A full-length pass marks the challenge solved in localStorage, per browser. Adding a challenge means adding a JSON file plus two array entries. Challenges 3 and 4 are new, gentler Quick versions of Black Friday and Celebrity tweet. The Practice presets stay byte-identical. Tests prove two things for every challenge: the bare starter fails it, and a reasonable design beats it. That makes the demo hold: "app server goes red, add a replica, pass".

**Accept (verbatim):** An ordered list of challenges as plain data (scenario id + one-line goal + optional hint): 3× spike, lose an app server, Black Friday, Celebrity tweet. After a run, a card suggests the next unsolved challenge, and picking it switches the scenario. All challenges are also listed. A pass marks the challenge solved in localStorage (per browser). Adding a challenge = adding a data entry.

Calls made in this plan (lead, please review):
1. **Challenge numbers, all verified with the engine** (headless sweep over app-server replicas 1–6 on T-7.3's exact starter graph, plus a Client → CDN → App → DB variant). Each challenge needs one more replica than the previous one, which gives a steady "goes red, scale, pass" ladder. The CDN offers a second route for 3 and 4.

   | # | id | load | bare starter (1 replica) | fails | passes |
   |---|---|---|---|---|---|
   | 1 | `quick-spike-3x` | 1500 RPS (same as starter), ×3 at 10 s for 10 s | fail, err 11.1 %, app overloaded | — | 2 replicas (p95 40 ms) |
   | 2 | `quick-lose-app-server` | 5000 RPS, kill 1 app_server at 10 s | fail, err 100 % | 2 replicas (err 20 %) | 3 replicas (p95 45 ms) |
   | 3 | `quick-black-friday` | 2000 → 8000 over 15 s, ×1.5 at 25 s for 8 s | fail, err 66.7 % | 3 replicas (p95 270 > 250) | 4 replicas (p95 65 ms); CDN + 1 replica |
   | 4 | `quick-celebrity-tweet` | 3000 RPS, 95 % reads, hotkey 0.5, ×5 at 10 s for 12 s | fail, err 73.3 % | 4 replicas (p95 222 > 200) | 5 replicas (p95 68 ms); CDN + 1 replica |

   The hotkey rule in #4 keeps the Celebrity flavour. It only affects storage nodes with more than one load-share unit, so it is harmless for these designs. Ids carry a `quick-` prefix so they never collide with the Practice `black-friday` / `celebrity-tweet` ids, which T-7.3's no-overlap test checks.
2. **Data shape:** `QuickChallenge = { scenarioId, goal, hint? }`. No separate id: the scenario id is the challenge's identity and its solved-state key. Order of `QUICK_CHALLENGES` is the suggestion order. `QUICK_SCENARIOS` lists the starter and then the four challenge scenarios in the same order.
3. **What counts as solved:** the verdict passed, `result.scenarioId === runScenario.id`, the scenario is a challenge, **and the run reached full length** (`frames.length >= round(durationSec × 10)`). A run stopped early never counts, because a 2-second run can "pass" before the spike arrives. Chaos from "Break it" during a run is allowed (it only makes the run harder).
4. **Next suggestion** is the first unsolved challenge in list order, skipping the one just solved. Solving out of order sends the user back to the earliest gap.
5. **Picking a challenge** (the "Try it" button or a list row) goes through T-7.5's `switchQuickScenario`, the same path as "More scenarios". It resets the sim, because the stale verdict and frames belong to the old scenario, and selects a fresh clone of the scenario. Rows and "Try it" are disabled while a run is running or paused, so a click can't silently abort the run. That disabled state gets a tooltip.
6. **Placement:** T-7.5's right-column slot, under the scenario summary (the column is `w-72`, so the card is `w-full`). It never overlaps the canvas overlays. **"All challenges are also listed"** lives in the same card. The header is always visible ("Challenges · n/4 solved") and toggles the full ordered list. Before the first run on the starter, the card is only that header, so nothing competes with Run.
7. **Solved storage:** one key, `bp:challenges:solved`, holding a JSON array of scenario ids. Reads are forgiving: bad JSON or a non-array gives `[]`, non-strings are dropped, duplicates removed. Writes are best-effort like `saveDesign`. The key can't collide with `listDesigns`' `bp:design:` prefix.

   ```ts
   /** Per-browser Quick-mode progress (not per design). */
   export const SOLVED_CHALLENGES_KEY = "bp:challenges:solved";

   function storage(): Storage | null {
     return typeof localStorage === "undefined" ? null : localStorage;
   }

   /** Forgiving guard: anything but a JSON array → []; keeps unique strings, in order. */
   export function parseSolvedChallenges(text: string): string[] {
     let value: unknown;
     try {
       value = JSON.parse(text);
     } catch {
       return [];
     }
     if (!Array.isArray(value)) return [];
     return [...new Set(value.filter((v): v is string => typeof v === "string"))];
   }

   export function loadSolvedChallenges(): string[] {
     try {
       const text = storage()?.getItem(SOLVED_CHALLENGES_KEY);
       return text == null ? [] : parseSolvedChallenges(text);
     } catch {
       return [];
     }
   }

   /** Idempotent. Returns the updated list even when the write fails (best-effort, like saveDesign). */
   export function markChallengeSolved(scenarioId: string): string[] {
     const current = loadSolvedChallenges();
     const next = current.includes(scenarioId) ? current : [...current, scenarioId];
     try {
       storage()?.setItem(SOLVED_CHALLENGES_KEY, JSON.stringify(next));
     } catch {
       // progress must never take the app down
     }
     return next;
   }
   ```

5. **Create `app/src/components/quick/challenge-nudge.ts`** (pure, no React):
   ```ts
   import type { RunResult, Scenario } from "@/lib/core";
   import type { QuickChallenge } from "@/lib/scenarios";
   import { TICKS_PER_SEC } from "@/lib/simulation";
   import type { SimStatus } from "@/stores/sim-store";

   /** True when the run reached the scenario's last tick (Stop finalizes early). */
   export function ranFullLength(result: RunResult, scenario: Scenario): boolean {
     return result.frames.length >= Math.round(scenario.durationSec * TICKS_PER_SEC);
   }

   /** The challenge this finished run solved, or null. */
   export function challengeSolvedBy(
     challenges: readonly QuickChallenge[],
     result: RunResult | null,
     scenario: Scenario | null,
   ): QuickChallenge | null {
     if (!result || !scenario) return null;
     if (!result.verdict.passed || result.scenarioId !== scenario.id) return null;
     if (!ranFullLength(result, scenario)) return null;
     return challenges.find((c) => c.scenarioId === scenario.id) ?? null;
   }

   /** First challenge in order that isn't solved and isn't `skip`. */
   export function nextUnsolvedChallenge(
     challenges: readonly QuickChallenge[],
     solved: readonly string[],
     skip?: string,
   ): QuickChallenge | null {
     return (
       challenges.find((c) => c.scenarioId !== skip && !solved.includes(c.scenarioId)) ?? null
     );
   }

   export type NudgeView =
     | { kind: "none" }
     | { kind: "active"; challenge: QuickChallenge; running: boolean }
     | { kind: "solved"; challenge: QuickChallenge; next: QuickChallenge | null }
     | { kind: "retry"; challenge: QuickChallenge; stopped: boolean }
     | { kind: "suggest"; next: QuickChallenge; /** full-length pass */ passed: boolean }
     | { kind: "all-done" };

   export interface NudgeInput {
     challenges: readonly QuickChallenge[];
     solved: readonly string[];
     /** the selected scenario (scenario-store) */
     scenarioId: string;
     status: SimStatus;
     result: RunResult | null;
     runScenario: Scenario | null;
   }

   export function describeNudge(input: NudgeInput): NudgeView {
     const { challenges, solved, scenarioId, status, result, runScenario } = input;
     const selected = challenges.find((c) => c.scenarioId === scenarioId) ?? null;
     if (status !== "done" || !result || !runScenario || runScenario.id !== scenarioId) {
       return selected
         ? { kind: "active", challenge: selected, running: status === "running" || status === "paused" }
         : { kind: "none" };
     }
     if (selected) {
       if (challengeSolvedBy(challenges, result, runScenario)) {
         return {
           kind: "solved",
           challenge: selected,
           next: nextUnsolvedChallenge(challenges, solved, selected.scenarioId),
         };
       }
       return { kind: "retry", challenge: selected, stopped: !ranFullLength(result, runScenario) };
     }
     const next = nextUnsolvedChallenge(challenges, solved);
     const held = result.verdict.passed && ranFullLength(result, runScenario);
     return next ? { kind: "suggest", next, passed: held } : { kind: "all-done" };
   }
   ```
