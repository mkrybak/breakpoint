# Plan T-3.1 — Scenario presets + requirements panel

## Goal

The `scenarios` engine (empty until now) ships its three built-in presets and
a loader; the design screen gains the controls that pick a scenario and edit
the NFRs it will be graded against. Concretely: `src/lib/scenarios/presets/`
gets `black-friday.json` (ramp+spike), `celebrity-tweet.json` (hotkey+spike),
and `az-outage.json` (kill+partition); `scenarios/index.ts` loads them through
a hand-rolled `parseScenario(data): Scenario | null` guard and exposes
`SCENARIO_PRESETS`, `listScenarioPresets()`, `getScenarioPreset(id)`, and a
pure `describeStressRule(rule): string` for the timeline preview. A new shell
store `scenario-store.ts` holds the working `Scenario` (a `structuredClone` of
the selected preset that the interviewer then edits). Two new client panels —
`ScenarioPanel.tsx` (preset picker + timeline preview) and
`RequirementsPanel.tsx` (base RPS, p95, error budget, strong-consistency
toggle) — read and write that store, wired into `design/[id]/page.tsx` in a
new right rail that leaves the existing `NodeConfigPanel` untouched. No sim run
yet — that store is what T-3.2 hands to the worker.

**Accept (verbatim from tasks/M3-stress-scenarios.md):**
3 presets: `black-friday` (ramp+spike), `celebrity-tweet` (hotkey+spike),
`az-outage` (kill+partition); RequirementsPanel edits `pass` criteria (RPS,
p95, error budget, consistency toggle); ScenarioPanel picks preset, shows
timeline preview.

The panels are **functional UI in the existing NodeConfigPanel style** (this
task reuses its Tailwind tokens, exactly as the plan/implement flow built that
panel in T-1.5). If the user wants richer visuals after reviewing at
localhost, that is a follow-up `/ui T-3.1` pass — not part of this
implementation.

- **Engines are pure.** `scenarios/index.ts` imports only `@/lib/core` and its

  plain data.
- **Public API via `index.ts`.** The panels and store import scenarios from
  `@/lib/scenarios` (never `@/lib/scenarios/presets/...` or an internal file).
- **Shell may import engines.** `scenario-store.ts` (a store) imports zustand
  and `@/lib/scenarios`; the panels import `@/stores/scenario-store` and
  `@/lib/scenarios`. That is allowed — the bans are inside `src/lib/**` only.
- **Do not modify any existing file except `design/[id]/page.tsx`,
  `scenarios/index.ts`, and the `.gitkeep` removal.** No changes to
  `NodeConfigPanel`, the simulation engine, or any test.
- **No new dependencies.** zustand, react, next are already present.

Decided during planning (implementer makes zero choices):

- **Presets are their own canonical copies** in `src/lib/scenarios/presets/`.
  `examples/black-friday.json` (the T-2.7 CLI demo input) is a separate file
  and stays as-is — the CLI reads files by path, the app reads presets by id.
  The two black-friday files are intentional duplicates (demo data vs app
  data); do not try to share them.
- **Loader through a guard, not casts.** JSON imports type as literals whose
  `rule`/`consistency` fields widen to `string`, so `as Scenario` is unsound.
  Instead every preset is passed (as `unknown`) through `parseScenario`, which
  validates and rebuilds a correctly-typed `Scenario`. Presets load at module
  init; a malformed preset throws immediately (surfaced by `npm test`).
  `parseScenario` returns `null` on bad input (mirroring
  `persistence/local.ts`'s `parseDesignRecord`) so M5's RunBundle import can
  reuse it verbatim.
- **`describeStressRule` uses raw numbers, no locale** — `at 10s — ramp to
  20000 RPS over 20s`, etc. Locale grouping would make the golden strings
  environment-dependent; raw digits keep the tests exact.
- **The working scenario is a deep clone.** `selectPreset` and the store's
  initial state `structuredClone` the preset so edits never mutate the shared
  `SCENARIO_PRESETS` objects. `structuredClone` is a global in Node 18+ and
  every target browser.
- **The strong-consistency toggle adds/removes `pass.consistency`.** On →
  `pass.consistency = "strong"`; off → `delete pass.consistency`. The type
  makes it optional, so absence is the "not required" state the verdict
  expects.
- **RPS in the RequirementsPanel is `scenario.baseRps`** (the offered-load
  NFR); it is not in `pass`, so it has its own store action `setBaseRps`.
  `pass` edits (`p95Ms`, `maxErrorRate`) go through `updatePass`.
- **New right rail, `NodeConfigPanel` untouched.** The page renders a new
  `<aside>` (width `w-72`, its own scroll) between `<main>` and
  `NodeConfigPanel`, stacking `<ScenarioPanel/>` then `<RequirementsPanel/>`
  as plain `<section>`s (they own no width/aside of their own). This adds a
  second right column and touches only the page file.
- **`scenario-store.ts` is a new store, not folded into `sim-store`.** T-3.2
  owns `sim-store.ts` (run state, frames). Scenario *selection + NFR editing*
  is a distinct concern; keeping it separate avoids pre-empting T-3.2, which
  will read `useScenarioStore.getState().scenario` to launch the worker.
- **Preset values** (hand-picked, valid ranges, illustrative — the demo tunes
  against specific graphs, not these numbers):
  - `black-friday` — 60s, base 5000, read 0.9, ramp→20000/20s at 10s, spike
    ×1.5/10s at 45s, budgets p95 250 / err 0.01, seed 42. (Same numbers as
    the T-2.7 CLI demo, so `npm run sim` and the preset agree.)
  - `celebrity-tweet` — 60s, base 15000, read 0.95, hotkey skew 0.5/40s at
    10s, spike ×3/15s at 25s, budgets p95 200 / err 0.02, seed 7.
  - `az-outage` — 60s, base 12000, read 0.8, kill app_server ×2 at 15s,
    partition db_sql/20s at 15s, budgets p95 300 / err 0.05,
    minSurvivedKills 1, seed 99. Rules target by **kind** so the preset works
    against any graph that has app servers and a SQL db.
- **Tests** (`tests/scenarios.test.ts`): the three preset ids in order; each
  preset's rule kinds; `getScenarioPreset` miss → `undefined`; every preset
  runs headless through `runSimulation` against a small inline graph to a full
  `durationSec × 10` frame array with a verdict (proves presets are valid and
  simulable); `parseScenario` accept/reject cases; `describeStressRule` golden
  strings for all six rule kinds. No store or panel tests — those are shell UI
  reviewed at localhost.

Entire file becomes:

```ts
import type { Scenario, StressRule } from "@/lib/core";
import azOutage from "./presets/az-outage.json";
import blackFriday from "./presets/black-friday.json";
import celebrityTweet from "./presets/celebrity-tweet.json";

function isRecord(v: unknown): v is Record<string, unknown> {
  return typeof v === "object" && v !== null;
}

function num(v: unknown): v is number {
  return typeof v === "number" && Number.isFinite(v);
}

function str(v: unknown): v is string {
  return typeof v === "string";
}

function parseRule(v: unknown): StressRule | null {
  if (!isRecord(v) || !num(v.at) || !str(v.rule)) return null;
  switch (v.rule) {
    case "ramp":
      return num(v.toRps) && num(v.overSec)
        ? { at: v.at, rule: "ramp", toRps: v.toRps, overSec: v.overSec }
        : null;
    case "spike":
      return num(v.factor) && num(v.forSec)
        ? { at: v.at, rule: "spike", factor: v.factor, forSec: v.forSec }
        : null;
    case "kill": {
      if (!str(v.target)) return null;
      const kill: Extract<StressRule, { rule: "kill" }> = {
        at: v.at,
        rule: "kill",
        target: v.target,
      };
      if (num(v.count)) kill.count = v.count;
      return kill;
    }
    case "flush":
      return v.target === "cache"
        ? { at: v.at, rule: "flush", target: "cache" }
        : null;
    case "partition":
      return str(v.target) && num(v.forSec)
        ? { at: v.at, rule: "partition", target: v.target, forSec: v.forSec }
        : null;
    case "hotkey":
      return num(v.skew) && num(v.forSec)
        ? { at: v.at, rule: "hotkey", skew: v.skew, forSec: v.forSec }
        : null;
    default:
      return null;
  }
}

function parsePass(v: unknown): Scenario["pass"] | null {
  if (!isRecord(v) || !num(v.p95Ms) || !num(v.maxErrorRate)) return null;
  const pass: Scenario["pass"] = { p95Ms: v.p95Ms, maxErrorRate: v.maxErrorRate };
  if (v.consistency !== undefined) {
    if (v.consistency !== "strong") return null;
    pass.consistency = "strong";
  }
  if (v.minSurvivedKills !== undefined) {
    if (!num(v.minSurvivedKills)) return null;
    pass.minSurvivedKills = v.minSurvivedKills;
  }
  return pass;
}

/**
 * Hand-rolled schema guard (02-data-model: "zod-free, scenarios-style") —
 * mirrors persistence's parseDesignRecord. Returns a freshly-built, correctly
 * typed Scenario, or null on any malformed field. Presets pass through it at
 * load; M5's RunBundle import reuses it for untrusted files.
 */
export function parseScenario(data: unknown): Scenario | null {
  if (!isRecord(data)) return null;
  if (!str(data.id) || !str(data.name) || !str(data.description)) return null;
  if (
    !num(data.durationSec) ||
    !num(data.baseRps) ||
    !num(data.readRatio) ||
    !num(data.seed)
  ) {
    return null;
  }
  if (!Array.isArray(data.timeline)) return null;
  const timeline: StressRule[] = [];
  for (const raw of data.timeline) {
    const rule = parseRule(raw);
    if (rule === null) return null;
    timeline.push(rule);
  }
  const pass = parsePass(data.pass);
  if (pass === null) return null;
  return {
    id: data.id,
    name: data.name,
    description: data.description,
    durationSec: data.durationSec,
    baseRps: data.baseRps,
    readRatio: data.readRatio,
    timeline,
    pass,
    seed: data.seed,
  };
}

function requirePreset(raw: unknown): Scenario {
  const scenario = parseScenario(raw);
  if (scenario === null) throw new Error("invalid scenario preset");
  return scenario;
}

/** The built-in scenarios (M3). Order is the dropdown order. */
export const SCENARIO_PRESETS: readonly Scenario[] = [
  requirePreset(blackFriday),
  requirePreset(celebrityTweet),
  requirePreset(azOutage),
];

export function listScenarioPresets(): readonly Scenario[] {
  return SCENARIO_PRESETS;
}

export function getScenarioPreset(id: string): Scenario | undefined {
  return SCENARIO_PRESETS.find((scenario) => scenario.id === id);
}

/** One human-readable timeline line for the ScenarioPanel preview. */
export function describeStressRule(rule: StressRule): string {
  switch (rule.rule) {
    case "ramp":
      return `at ${rule.at}s — ramp to ${rule.toRps} RPS over ${rule.overSec}s`;
    case "spike":
      return `at ${rule.at}s — spike ×${rule.factor} for ${rule.forSec}s`;
    case "kill":
      return `at ${rule.at}s — kill ${rule.count ?? 1} × ${rule.target}`;
    case "flush":
      return `at ${rule.at}s — flush ${rule.target}`;
    case "partition":
      return `at ${rule.at}s — partition ${rule.target} for ${rule.forSec}s`;
    case "hotkey":
      return `at ${rule.at}s — hotkey skew ${rule.skew} for ${rule.forSec}s`;
  }
}
```

### 6. Create `app/src/stores/scenario-store.ts`

Entire file:

```ts
import { create } from "zustand";
import type { Scenario } from "@/lib/core";
import { getScenarioPreset, SCENARIO_PRESETS } from "@/lib/scenarios";

const DEFAULT_PRESET = SCENARIO_PRESETS[0];

interface ScenarioStore {
  /** The working scenario: a preset clone with the interviewer's NFR edits. */
  scenario: Scenario;
  /** Replace the working scenario with a fresh clone of a preset. */
  selectPreset: (id: string) => void;
  /** Edit the offered base load (RequirementsPanel). */
  setBaseRps: (rps: number) => void;
  /** Patch the numeric NFR budgets (RequirementsPanel). */
  updatePass: (patch: { p95Ms?: number; maxErrorRate?: number }) => void;
  /** Toggle the strong-consistency NFR on/off. */
  setStrongConsistency: (on: boolean) => void;
}

export const useScenarioStore = create<ScenarioStore>((set) => ({
  scenario: structuredClone(DEFAULT_PRESET),

  selectPreset: (id) =>
    set(() => ({
      scenario: structuredClone(getScenarioPreset(id) ?? DEFAULT_PRESET),
    })),

  setBaseRps: (rps) =>
    set((s) => ({ scenario: { ...s.scenario, baseRps: rps } })),

  updatePass: (patch) =>
    set((s) => ({
      scenario: { ...s.scenario, pass: { ...s.scenario.pass, ...patch } },
    })),

  setStrongConsistency: (on) =>
    set((s) => {
      const pass = { ...s.scenario.pass };
      if (on) pass.consistency = "strong";
      else delete pass.consistency;
      return { scenario: { ...s.scenario, pass } };
    }),
}));
```

**b. `app/src/components/panels/RequirementsPanel.tsx`** — entire file:

```tsx
"use client";

import { useScenarioStore } from "@/stores/scenario-store";

const HEADING =
  "text-xs font-semibold tracking-wide text-neutral-400 uppercase";
const FIELD_LABEL =
  "text-[10px] font-medium tracking-wider text-neutral-500 uppercase";
const INPUT =
  "mt-1 w-full rounded border border-neutral-700 bg-neutral-800 px-2 py-1 text-xs text-neutral-100";

export function RequirementsPanel() {
  const scenario = useScenarioStore((s) => s.scenario);
  const setBaseRps = useScenarioStore((s) => s.setBaseRps);
  const updatePass = useScenarioStore((s) => s.updatePass);
  const setStrongConsistency = useScenarioStore((s) => s.setStrongConsistency);

  return (
    <section>
      <h2 className={HEADING}>Requirements</h2>
      <div className="mt-2 space-y-3">
        <NumberField
          label="Base RPS"
          value={scenario.baseRps}
          min={0}
          step={500}
          onChange={setBaseRps}
        />
        <NumberField
          label="p95 budget (ms)"
          value={scenario.pass.p95Ms}
          min={1}
          step={10}
          onChange={(value) => updatePass({ p95Ms: value })}
        />
        <NumberField
          label="Max error rate (0–1)"
          value={scenario.pass.maxErrorRate}
          min={0}
          max={1}
          step={0.005}
          onChange={(value) => updatePass({ maxErrorRate: value })}
        />
        <label className="flex items-center gap-2">
          <input
            type="checkbox"
            checked={scenario.pass.consistency === "strong"}
            onChange={(event) => setStrongConsistency(event.target.checked)}
          />
          <span className="text-xs text-neutral-300">
            Require strong consistency
          </span>
        </label>
      </div>
    </section>
  );
}

function NumberField({
  label,
  value,
  min,
  max,
  step,
  onChange,
}: {
  label: string;
  value: number;
  min?: number;
  max?: number;
  step?: number;
  onChange: (value: number) => void;
}) {
  return (
    <label className="block">
      <span className={FIELD_LABEL}>{label}</span>
      <input
        type="number"
        min={min}
        max={max}
        step={step}
        value={value}
        onChange={(event) => {
          const next = event.target.valueAsNumber;
          if (Number.isNaN(next)) return;
          let clamped = next;
          if (min !== undefined) clamped = Math.max(clamped, min);
          if (max !== undefined) clamped = Math.min(clamped, max);
          onChange(clamped);
        }}
        className={INPUT}
      />
    </label>
  );
}
```
