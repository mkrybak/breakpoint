# Plan — T-5.4 Polish pass

## Goal

When done, the app has product-grade polish on its shell: the landing page shows
the three built-in stress-test scenarios as informational cards; empty states are
friendly cards (not bare text) on the landing and on the empty canvas; the app
recovers gracefully from render errors and bad routes via Next.js error
boundaries; and the desktop-first workspaces stay readable on small screens with
a non-blocking advisory bar. No engine or simulation code changes.

**Acceptance criteria (verbatim from `tasks/M5-persistence-and-deploy.md`):**

> Landing page with scenario cards; empty states; error boundaries; mobile at
> least readable; run through full flow twice with fresh eyes and file bugs as
> new checkboxes here.

The final "run through the full flow twice … file bugs" item is a **manual QA
step for the user** (browser review, per the project's no-Playwright workflow).
This plan delivers the concrete polish items; Step 8 hands the walkthrough back.

## Context

Read before starting:

- `01-architecture.md` — engine-modularity rule and repo layout.
- `app/src/components/landing/LandingScreen.tsx` — the landing client component (designs list + create).
- `app/src/lib/scenarios/index.ts` — `listScenarioPresets()`, `describeStressRule(rule)`, `Scenario` shape (via `@/lib/core`).
- `app/src/components/canvas/DesignCanvas.tsx` — canvas; already renders `<Panel>` overlays (lock notice, warnings).
- `app/src/app/design/[id]/page.tsx`, `app/src/app/review/[runId]/page.tsx`, `app/src/components/review/ReviewScreen.tsx` — the workspace pages to make mobile-readable.
- `app/src/app/layout.tsx` — root layout (`body` is `min-h-full flex flex-col`).

**Engine rules that apply:** all new code lives in `src/app/**` and
`src/components/**` — the UI shell — so it may import from `@/lib/*` public
`index.ts` barrels. Do **not** add `react`/`next`/`zustand`/`@xyflow` imports
inside `src/lib/**` (none of this task touches `src/lib/**`). Scenario data is a
plain-data contract; read it via `listScenarioPresets()` / `describeStressRule()`
only — do not reach into preset JSON directly.

**Decisions already made (implementer does not choose):**

- **Scenario cards are informational, not actionable.** They describe the
  stress tests a design will face; they do not create or preload a design
  (scenario selection stays inside the workspace via `ScenarioPanel`). This keeps
  T-5.4 a polish task with no new URL/state plumbing.
- **Error boundaries = the idiomatic Next.js App Router trio**: `error.tsx`
  (route render errors), `global-error.tsx` (root-layout errors), `not-found.tsx`
  (404s). No third-party error-boundary library.
- **Mobile handling = a `lg:hidden` advisory bar** at the top of each workspace
  page, plus making those pages flex-column so the bar doesn't clip the `h-dvh`
  workspace. The landing is already responsive and gets **no** bar.

## Steps

### Step 1 — Scenario cards component

Create `app/src/components/landing/ScenarioCards.tsx`:

```tsx
import { listScenarioPresets, describeStressRule } from "@/lib/scenarios";

const CARD = "rounded-xl border border-neutral-800 bg-neutral-900/60 p-4";

export function ScenarioCards() {
  const scenarios = listScenarioPresets();
  return (
    <section className="mb-8">
      <h2 className="mb-1 text-xs font-semibold tracking-wide text-neutral-400 uppercase">
        Built-in stress tests
      </h2>
      <p className="mb-3 text-xs text-neutral-500">
        Every design is graded by surviving one of these. Pick a scenario inside
        the workspace.
      </p>
      <ul className="grid gap-3 sm:grid-cols-2">
        {scenarios.map((s) => (
          <li key={s.id} className={CARD}>
            <h3 className="text-sm font-semibold text-neutral-100">{s.name}</h3>
            <p className="mt-1 text-xs text-neutral-400">{s.description}</p>
            <p className="mt-2 text-xs text-neutral-500">
              {s.baseRps.toLocaleString("en-US")} RPS base · {s.durationSec}s ·{" "}
              {Math.round(s.readRatio * 100)}% reads
            </p>
            <p className="mt-1 text-xs text-neutral-500">
              Target: p95 ≤ {s.pass.p95Ms}ms · errors ≤{" "}
              {Math.round(s.pass.maxErrorRate * 100)}%
              {s.pass.consistency === "strong" ? " · strong consistency" : ""}
            </p>
            {s.timeline.length > 0 && (
              <ul className="mt-2 space-y-0.5">
                {s.timeline.map((rule, i) => (
                  <li key={i} className="text-xs text-neutral-600">
                    {describeStressRule(rule)}
                  </li>
                ))}
              </ul>
            )}
          </li>
        ))}
      </ul>
    </section>
  );
}
```

Notes: `key={i}` on the timeline list is acceptable here (static, never
reordered); if `react/no-array-index-key` fires under `npm run lint`, change it to
`key={`${rule.rule}-${rule.at}-${i}`}`.

### Step 4 — Route error boundary

Create `app/src/app/error.tsx`:

```tsx
"use client";

import { useEffect } from "react";
import Link from "next/link";

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  useEffect(() => {
    console.error(error);
  }, [error]);

  return (
    <main className="flex flex-1 flex-col items-center justify-center gap-4 bg-neutral-950 p-6 text-center text-neutral-100">
      <div>
        <h1 className="text-lg font-semibold">Something broke</h1>
        <p className="mt-1 max-w-md text-sm text-neutral-400">
          The screen hit an unexpected error. Your saved designs are safe in this
          browser.
        </p>
      </div>
      <div className="flex items-center gap-2">
        <button
          type="button"
          onClick={reset}
          className="rounded-lg border border-neutral-700 bg-neutral-900 px-3 py-1.5 text-xs font-medium text-neutral-200 hover:border-neutral-500"
        >
          Try again
        </button>
        <Link
          href="/"
          className="rounded-lg border border-neutral-700 bg-neutral-900 px-3 py-1.5 text-xs font-medium text-neutral-200 hover:border-neutral-500"
        >
          Back to designs
        </Link>
      </div>
    </main>
  );
}
```

### Step 5 — Global (root-layout) error boundary

Create `app/src/app/global-error.tsx`. It must render its own `<html>`/`<body>`
because it replaces the root layout when the layout itself errors:

```tsx
"use client";

export default function GlobalError({
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  return (
    <html lang="en">
      <body className="flex min-h-screen flex-col items-center justify-center gap-4 bg-neutral-950 p-6 text-center text-neutral-100">
        <div>
          <h1 className="text-lg font-semibold">Something broke</h1>
          <p className="mt-1 text-sm text-neutral-400">
            Reload the page to continue.
          </p>
        </div>
        <button
          type="button"
          onClick={reset}
          className="rounded-lg border border-neutral-700 bg-neutral-900 px-3 py-1.5 text-xs font-medium text-neutral-200 hover:border-neutral-500"
        >
          Try again
        </button>
      </body>
    </html>
  );
}
```

The `error` param is declared (to match Next's expected signature) but unused;
if `@typescript-eslint/no-unused-vars` flags it, prefix with underscore:
`_error` is not valid for a destructured object key — instead keep the type on
the object and omit `error` from the destructure entirely (only `{ reset }`),
leaving the type annotation as `{ error: Error & { digest?: string }; reset: () => void }`.
Adjust to `export default function GlobalError({ reset }: { error: ...; reset: ... })`.
