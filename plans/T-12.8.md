# T-12.8 — Right sidebar only when it's needed

## Goal

The far-right inspector column (`NodeConfigPanel`: Design / Node / Edge) is mounted permanently in both workspaces and takes 256 px even when nothing is selected. After this task it isn't rendered at all with nothing selected. Selecting exactly one node, or exactly one edge, opens it as a column to the right of the canvas, below the metrics bar. Deselecting (pane click, the panel's new close button, Delete) closes it. Export JSON / Import JSON move into a new icon-only "⋯" menu ("Design file") at the right end of the metrics bar in both Quick and Practice. Dropping a `.json` file on the canvas imports it, and the canvas shows a drop overlay while a file is dragged over it. Practice's middle column (scenario / requirements / notes / event log) is unchanged.

**Accept (verbatim):** The right inspector column (Design / Node / Edge) isn't a permanent ~250px strip. With nothing selected it is hidden (or collapsed to a thin rail), and the canvas gets the width. Selecting a node or edge opens it; deselecting closes it. Export JSON / Import JSON move out of the sidebar into a top-bar menu (a "⋯" / File menu) in both Quick and Practice; import still accepts a dropped file. The open/close doesn't jump the canvas viewport. Screenshots at 1440×900 and 1280×800, before and after, for both modes. Source: user feedback 2026-11-07 ("right sidebar takes a lot of space, export/import isn't always needed").

## Context

Read first: `app/src/components/panels/NodeConfigPanel.tsx`, `app/src/components/layout/PracticeWorkspace.tsx`, `app/src/components/quick/QuickWorkspace.tsx`, `app/src/components/quick/MenuButton.tsx`, `app/src/components/quick/QuickMenus.tsx`, `app/src/components/hud/MetricsBar.tsx`, `app/src/components/canvas/DesignCanvas.tsx`, `app/src/stores/design-store.ts` (selection, `importRecord`, autosave subscription), `app/src/persistence/local.ts` (`buildDesignRecord`, `parseDesignRecord`, `exportDesignFile`), `app/e2e/quick.spec.ts`, `app/e2e/smoke.spec.ts`.

**Design calls (lead, review):**
- **Hidden, not a thin rail.** With nothing selected the column isn't rendered. A rail would cost about 40 px and hold nothing: its only content would be a "select something" hint, and clicking a node is the universal gesture. The Verdict's existing copy already says "Select a node to change its settings." This only changes how the empty state looks, not how the panel works, so I'm not asking the user.
- **The panel pushes the canvas instead of floating over it, and only the canvas row narrows.** The inspector is a sibling of the canvas inside `<main>`, below the MetricsBar, so the metrics bar and its cards never reflow. An overlay would hide the Verdict: at 1280 px the canvas is 768 px and the centred `max-w-md` (448 px) verdict would sit under a 256 px panel. A column next to it doesn't hide anything.
- **No viewport jump.** React Flow keeps its transform when its container resizes. It only stores the new width and height (`useResizeHandler` in `@xyflow/react`), and `fitView` runs once at mount. So nodes keep their screen positions on open and close, and only the right edge of the canvas is covered or revealed. The canvas element must never remount: the inspector renders *after* the canvas wrapper as a conditional sibling, so the canvas keeps its position in the tree. There's no width animation, which avoids resizing React Flow every frame. Known trade-off: a node selected in the right-most 256 px of the canvas ends up behind the panel's edge until the user pans. Auto-panning would be exactly the jump the criteria forbid.
- **When it opens:** exactly one node selected, or no nodes and exactly one edge (the current `selected` / `selectedEdge` rules, unchanged). A multi-selection shows nothing, because there's nothing to edit. The Design section is gone, so the panel shows only a "Node" or an "Edge" section, with a close (×) button that clears the selection.
- **The File menu is an icon-only "⋯" (`Ellipsis`) named "Design file"**, at the far right of the MetricsBar in both variants (same spot relative to the canvas in both modes), right-aligned so it stays inside the viewport. Practice's PhaseBar isn't used because Quick has no equivalent full-width bar. `MenuButton` stays in `components/quick/` (shell can import shell). Moving it would only churn imports.
- **Dropping a file:** a file dropped anywhere on the canvas goes through the same import as the menu. The canvas lock doesn't block it, because the old Import button ignored the lock too. Bonus: today, dropping a JSON file on the page makes the browser navigate to it. A failed import (menu or drop) shows one red alert under the ⋯ trigger, from a small shared store, until it's dismissed or the next import succeeds. The ImportDropzone on the review screen is a different flow (run bundles + navigation) and isn't reused.
- Export and import read the attached design from `useDesignStore` (`designId` is set before a workspace renders, see `DesignWorkspace`), so `NodeConfigPanel` loses its `designId` prop.

**Rules:** this is shell-only work. Nothing in `src/lib/**` changes. Components and stores may import any engine through its `index.ts`, and `stores/` may import `persistence/` (as `design-store.ts` already does). No new runtime dependency: `Ellipsis`, `Download`, `Upload` and `X` come from `lucide-react`, which is already a dependency.

**Expected deviations from the Files list:** new `src/components/panels/DesignFileMenu.tsx`, new `src/stores/design-file-store.ts`, plus edits to `MenuButton.tsx`, `MetricsBar.tsx` (new `menu` prop), `DesignCanvas.tsx` (file drop), `design-store.ts` (`clearSelection`), tests, e2e, `01-architecture.md`, and the M12 Decisions. `QuickMenus.tsx` isn't touched.

**Batch overlap:** T-12.5 and T-12.6 also edit `MetricsBar.tsx` (the `Metric` popover and scrubbed values). This task adds one prop and one trailing element per bar and changes nothing else there, so it rebases trivially. T-12.7 changes `INPUT` (a taller min-height) in `panels/styles.ts`, which the inspector uses unchanged. T-12.3 and T-12.4 touch `FlowEdge.tsx` only.

2. **New `app/src/stores/design-file-store.ts`:**
   ```ts
   import { create } from "zustand";
   import { buildDesignRecord, exportDesignFile, parseDesignRecord } from "@/persistence/local";
   import { useDesignStore } from "./design-store";

   export const INVALID_DESIGN_FILE = "Not a valid design file";
   export const UNREADABLE_DESIGN_FILE = "Could not read that file";

   interface DesignFileStore {
     /** message from the last failed import (menu or canvas drop); null when none */
     importError: string | null;
     dismissImportError: () => void;
   }

   /** Export/import of the attached design (T-12.8): shared by the ⋯ menu and the canvas drop. */
   export const useDesignFileStore = create<DesignFileStore>((set) => ({
     importError: null,
     dismissImportError: () => set({ importError: null }),
   }));

   /** Download the attached design as `<slug>.design.json`. No-op before a design is attached. */
   export function exportCurrentDesign(): void {
     const s = useDesignStore.getState();
     if (s.designId === null) return;
     exportDesignFile(
       buildDesignRecord(s.designId, s.designName, s.graph, s.designMode, s.phaseNotes, s.actionLog),
     );
   }

   /** Replace the attached design with a file's graph, name, notes and log (mode kept, T-7.2). Returns whether it imported. */
   export async function importDesignFile(file: File): Promise<boolean> {
     let text: string;
     try {
       text = await file.text();
     } catch {
       useDesignFileStore.setState({ importError: UNREADABLE_DESIGN_FILE });
       return false;
     }
     const record = parseDesignRecord(text);
     if (record === null) {
       useDesignFileStore.setState({ importError: INVALID_DESIGN_FILE });
       return false;
     }
     useDesignStore.getState().importRecord(record);
     useDesignFileStore.setState({ importError: null });
     return true;
   }
   ```
