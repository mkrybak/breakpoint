# T-13.6 — Boards on the review screen and in the report

## Goal

The grader sees the candidate's three step boards. The review screen gains a tab strip over its main area: **Design · Requirements · Entities · API**, each board tab showing an item count. A board tab renders the T-13.3/4/5 component in read-only mode, from the `boards` value the screen passes in. That value comes from design-store in every flow: in-session, after a cold reload, and after a bundle import, since `ImportDropzone` saves the bundle's design and `attachDesign` loads it. `buildReviewReport` gains `## Requirements`, `## Entities` and `## API` sections. An e2e test runs the whole milestone demo, ending with a bundle import in a fresh browser context.

**Accept (verbatim):**
- The review screen shows all three boards read-only: requirement lists, the entity diagram with crow's-foot lines, and endpoint cards. It works after a bundle import (not just in-session).
- `buildReviewReport` adds a section per board: requirements as bullet lists, entities as `Name` + fields with a relations list using words ("User 1 → many Order"), and endpoints as `METHOD url → status` with fenced JSON bodies. The existing notes stay in the report.
- An e2e test runs the milestone demo end to end through export → import → review.
- Screenshots: review screen with all three boards.

**Calls made here (lead, review):**
1. **Layout: tabs over the main area, not boards squeezed into the right column.** The right column (w-80, notes and scorecard) is too narrow for two requirement columns, side-by-side JSON bodies or a readable entity diagram. Tabs mirror the workspace, where a board takes the canvas spot, and show each board at the size the candidate used. The notes stay in the right column next to every tab, which is the milestone's "next to the notes". The board tab labels carry counts (`Entities 3`), so empty boards are visible at a glance. Selecting a timeline event switches to Design, since snapshots are graph-only. Verdict and scrubber render only on the Design tab, as today. An empty board tab shows one muted line instead of mounting the component.
2. `nothingToReview` also requires empty boards, so a design that has only boards still opens its review.
3. **Report placement:** the three sections go between `## Scores` and `## Simulation verdict`.
   - Blank requirement items and blank fields are skipped. An empty board prints `_Nothing written._`.
   - Seeded NFRs get ` _(scenario)_`.
   - Relations use `RELATION_ENDS` words (`1` / `many`) with `→`. Relations naming a missing entity are skipped.
   - Endpoints: `### METHOD url → status` (`(no URL)` when the URL is blank, and ` → status` omitted when it's blank). Each non-blank body is a `**Request**` / `**Response**` label plus a ```` ```json ```` fence, whose length grows past any backtick run in the body, so a body containing ```` ``` ```` can't break out of it. Bodies are verbatim, with no trimming.
4. **e2e seeds a runnable Practice record with no `boards` field.** Export bundle needs a run result, and Run needs a graph, and drawing one by drag-and-drop would dwarf the test. The seed is Client → App server (1 replica) → SQL database, which `npx tsx scripts/sim.ts` confirms logs "App server overloaded at 4k RPS" at t=0 under Black Friday. It also exercises review focus 5: an old record gets empty boards, then is seeded. The import runs in `browser.newContext()`, which has empty localStorage and fresh stores, so it proves the bundle alone carries the boards. Playwright 1.65 applies the config's `baseURL` and viewport to `browser.newContext()` (`runBeforeCreateBrowserContext`).

   export type BoardKey = keyof DesignBoards; // "requirements" | "entities" | "api"
   export type BoardCounts = Record<BoardKey, number>;

   /** What a grader would see per board: non-blank requirements, entities, endpoints. */
   export function boardCounts(boards: DesignBoards): BoardCounts {
     const { functional, nonFunctional } = boards.requirements;
     return {
       requirements: [...functional, ...nonFunctional].filter((i) => i.text.trim() !== "").length,
       entities: boards.entities.entities.length,
       api: boards.api.endpoints.length,
     };
   }

   export function hasBoardContent(counts: BoardCounts): boolean {
     return counts.requirements + counts.entities + counts.api > 0;
   }

   ```ts
   const NOTHING_WRITTEN = "_Nothing written._";

   const RELATION_ENDS: Record<RelationKind, readonly [string, string]> = {
     "one-to-one": ["1", "1"],
     "one-to-many": ["1", "many"],
     "many-to-one": ["many", "1"],
     "many-to-many": ["many", "many"],
   };

   /** A relation in words, read from → to: "User 1 → many Order". */
   export function relationPhrase(from: string, to: string, kind: RelationKind): string {
     const [fromEnd, toEnd] = RELATION_ENDS[kind];
     return `${from} ${fromEnd} → ${toEnd} ${to}`;
   }

   function orFallback(text: string, fallback: string): string {
     const t = text.trim();
     return t === "" ? fallback : t;
   }

   /** Fenced block whose fence is longer than any backtick run in the body (verbatim body). */
   function fenced(body: string, lang: string): string[] {
     const longest = Math.max(0, ...(body.match(/`+/g) ?? []).map((run) => run.length));
     const fence = "`".repeat(Math.max(3, longest + 1));
     return [`${fence}${lang}`, body, fence];
   }

   function requirementsSection(board: RequirementsBoard): string[] {
     const columns = [
       ["Functional", board.functional],
       ["Non-functional", board.nonFunctional],
     ] as const;
     const filled = columns.map(
       ([title, items]) => [title, items.filter((i) => i.text.trim() !== "")] as const,
     );
     const lines = ["## Requirements", ""];
     if (filled.every(([, items]) => items.length === 0)) return [...lines, NOTHING_WRITTEN, ""];
     for (const [title, items] of filled) {
       lines.push(`**${title}**`, "");
       if (items.length === 0) lines.push("_None._");
       for (const item of items) {
         lines.push(`- ${item.text.trim()}${item.source === "scenario" ? " _(scenario)_" : ""}`);
       }
       lines.push("");
     }
     return lines;
   }

   function entitiesSection(board: EntitiesBoard): string[] {
     const lines = ["## Entities", ""];
     if (board.entities.length === 0) return [...lines, NOTHING_WRITTEN, ""];
     const nameById = new Map(board.entities.map((e) => [e.id, orFallback(e.name, "(unnamed)")]));
     for (const entity of board.entities) {
       lines.push(`**${orFallback(entity.name, "(unnamed)")}**`, "");
       const fields = entity.fields.filter((f) => f.name.trim() !== "" || f.type.trim() !== "");
       if (fields.length === 0) lines.push("_No fields._");
       for (const field of fields) {
         const type = field.type.trim();
         lines.push(`- ${orFallback(field.name, "(unnamed)")}${type === "" ? "" : `: ${type}`}`);
       }
       lines.push("");
     }
     const phrases = board.relations.flatMap((r) => {
       const from = nameById.get(r.from);
       const to = nameById.get(r.to);
       return from !== undefined && to !== undefined ? [relationPhrase(from, to, r.kind)] : [];
     });
     if (phrases.length > 0) {
       lines.push("**Relationships**", "", ...phrases.map((p) => `- ${p}`), "");
     }
     return lines;
   }

   function apiSection(board: ApiBoard): string[] {
     const lines = ["## API", ""];
     if (board.endpoints.length === 0) return [...lines, NOTHING_WRITTEN, ""];
     for (const endpoint of board.endpoints) {
       const status = endpoint.status.trim();
       lines.push(
         `### ${endpoint.method} ${orFallback(endpoint.url, "(no URL)")}${status === "" ? "" : ` → ${status}`}`,
         "",
       );
       const bodies = [
         ["Request", endpoint.requestBody],
         ["Response", endpoint.responseBody],
       ] as const;
       for (const [title, body] of bodies) {
         if (body.trim() === "") continue;
         lines.push(`**${title}**`, "", ...fenced(body, "json"), "");
       }
     }
     return lines;
   }
   ```
