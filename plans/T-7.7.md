# T-7.7 — Quick → Practice link + docs (plan)

## Goal

Quick mode gets a quiet way into the full product: a "Try a full practice interview" button in the Quick workspace's right column. One click creates a **new, blank Practice design** (the Quick design is not converted and stays in the saved list) and opens it at the start of a fresh interview. Then the docs catch up with M7. `01-architecture.md` gets a "Product modes" section and lists every file M7 added, and the vault README status board marks M7 done. A browser test walks the whole new front door: landing → Quick → Run → Passed → link → fresh Practice design.

> Quick mode links to "Try a full practice interview", which starts a *new* Practice design (no conversion in v1). `01-architecture` describes the three modes and the new files, and the README status board is updated.

**UX decision (lead, please review): what "starts a new Practice design" means.** The button behaves exactly like the landing Practice card submitted with an empty name. It creates `newPracticeDesign(uuid, "")` (named "Untitled design", which can be renamed on the landing page), saves it, and opens `/design/<new id>` in the same tab with `router.push`. I rejected routing to `/` so the user could name it first: that costs an extra click and a context switch for a name that is optional on the Practice card anyway, and the spec says the link *starts* a design. Copy around the button says "Opens a new blank design. This one stays in your saved designs." so nobody expects their Quick design to carry over.

**Why stale state can't leak** (no design-to-design navigation existed before this task):
- Sim + scenario: QuickWorkspace unmounts on navigation, and its cleanup `leaveQuickMode()` resets the sim (stopping any live run's worker) and restores Black Friday (T-7.5).
- Layout: DesignWorkspace gates on `attachedId === designId`, so it shows blank until the new id is attached, then the Practice layout.
- Phase clock: `usePhaseStore` is global, and nothing resets it between designs. The click handler calls `usePhaseStore.getState().reset()` so the new interview starts at Requirements with 05:00. While the Quick design is still attached, the phase-change subscription's `recordInterviewAction` returns early for Quick (T-7.5 guard), so the reset records nothing.
- Unmounting: `next.config.ts` doesn't enable `cacheComponents`, so pages really unmount on navigation (no `<Activity>` state preservation). The landing page also remounts after browser back, with T-7.4's `creating` flag set to false again.
- The e2e test asserts all of this in a real browser, including a Practice session earlier in the same tab.

Known limitation, not fixed here: an edit made less than 0.5 s before clicking may not be autosaved, because the debounced timer fires after the new design is attached. The same is already true when leaving any design.

Deviations from the task's Files list: new `src/components/quick/TryPracticeLink.tsx` and `e2e/quick-to-practice.spec.ts`. Also edits `tasks/M7-quick-mode.md` (tick, frontmatter, Decisions).

### 1. `app/src/components/quick/TryPracticeLink.tsx` (new, `"use client"`)

```tsx
"use client";

import { useState } from "react";
import { useRouter } from "next/navigation";
import { ArrowRight, GraduationCap } from "lucide-react";
import { newPracticeDesign } from "@/components/landing/new-design";
import { saveDesign } from "@/persistence/local";
import { usePhaseStore } from "@/stores/phase-store";

/**
 * Quick → Practice (T-7.7): starts a *new* blank Practice design, never a
 * conversion (product-modes spec, "Moving between modes"). Same record as the
 * landing Practice card with an empty name.
 */
export function TryPracticeLink() {
  const router = useRouter();
  const [opening, setOpening] = useState(false);

  const onClick = () => {
    if (opening) return;
    setOpening(true);
    const record = newPracticeDesign(crypto.randomUUID(), "");
    saveDesign(record);
    // The phase clock is global and nothing else resets it: a new interview
    // starts at Requirements with a full budget. Sim + scenario are reset by
    // QuickWorkspace's unmount (leaveQuickMode, T-7.5).
    usePhaseStore.getState().reset();
    router.push(`/design/${record.id}`);
  };

  return (
    <section
      aria-labelledby="try-practice-title"
      className="rounded-xl border border-neutral-800 bg-neutral-900/60 p-3"
    >
      <div className="flex items-center gap-2">
        <GraduationCap className="h-4 w-4 shrink-0 text-neutral-400" aria-hidden />
        <h2
          id="try-practice-title"
          className="text-xs font-semibold tracking-wide text-neutral-400 uppercase"
        >
          Practice mode
        </h2>
      </div>
      <p className="mt-2 text-xs leading-snug text-neutral-400">
        Ready for the real thing? Run the full interview: timed phases,
        requirements, notes and a self-review scorecard.
      </p>
      <button
        type="button"
        onClick={onClick}
        disabled={opening}
        className="group mt-3 flex h-8 w-full items-center justify-center gap-1.5 rounded-lg border border-neutral-700 bg-neutral-900 px-3 text-xs font-medium text-neutral-200 transition-colors duration-150 hover:border-neutral-500 hover:bg-neutral-800 focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-sky-300 disabled:cursor-wait disabled:opacity-60"
      >
        Try a full practice interview
        <ArrowRight
          className="h-3.5 w-3.5 transition-transform duration-150 group-hover:translate-x-0.5"
          aria-hidden
        />
      </button>
      <p className="mt-2 text-[11px] leading-snug text-neutral-500">
        Opens a new blank design. This one stays in your saved designs.
      </p>
    </section>
  );
}
```

The button's accessible name must be exactly `Try a full practice interview` (the icon is `aria-hidden`), because the e2e relies on it. It is deliberately neutral (no sky fill) so it never competes with Run.

### 3. `app/e2e/quick-to-practice.spec.ts` (new)

It's also the only test that covers the whole M7 demo path in one go (saved-list Quick design → T-7.5 layout → worker → verdict → T-7.6 card → this link; T-7.4's Quick card is covered by `landing.spec.ts`).
```ts
import { expect, test, type Page } from "@playwright/test";

const DESIGN_URL = /\/design\/[0-9a-f-]{36}$/;
const QUICK_ID = "e2e-quick-start";
const QUICK_NAME = "E2E Quick start";
/** Inline copy of T-7.3's starter graph (components/quick/starter.ts) — no src/ imports in e2e. */
const QUICK_RECORD = {
  id: QUICK_ID,
  name: QUICK_NAME,
  mode: "quick",
  scenarioId: "",
  graph: {
    entryNodeId: "client",
    nodes: [
      { id: "client", kind: "client", label: "Client", position: { x: 0, y: 0 }, config: {} },
      { id: "app", kind: "app_server", label: "App server", position: { x: 280, y: 0 }, config: { replicas: 1 } },
      { id: "db", kind: "db_sql", label: "SQL database", position: { x: 560, y: 0 }, config: { replicas: 0, sharded: false, readYourWrites: false } },
    ],
    edges: [
      { id: "e-client-app", source: "client", target: "app", trafficShare: 1, kind: "sync" },
      { id: "e-app-db", source: "app", target: "db", trafficShare: 1, kind: "sync" },
    ],
  },
  updatedAt: "2026-11-05T00:00:00.000Z",
};

function row(page: Page, name: string) {
  return page
    .getByRole("listitem")
    .filter({ has: page.getByRole("link", { name, exact: true }) });
}

test("landing → Quick → Run → Passed → Try a full practice interview → fresh Practice design", async ({
  page,
}) => {
  // An existing Quick design, opened from the saved list (the landing Quick *card*
  // resets the phase clock itself since T-7.4, so it can't prove the link's reset).
  await page.addInitScript(
    ({ key, value }) => {
      if (!window.localStorage.getItem(key)) window.localStorage.setItem(key, value);
    },
    { key: `bp:design:${QUICK_ID}`, value: JSON.stringify(QUICK_RECORD) },
  );

  // In-tab history: an earlier Practice session leaves the global phase clock at
  // High-level design. Browser back is a client-side navigation, so stores survive.
  await page.goto("/");
  await page.getByLabel("Practice design name").fill("Warm-up");
  await page.getByRole("button", { name: "New design", exact: true }).click();
  await expect(page).toHaveURL(DESIGN_URL);
  for (let i = 0; i < 3; i++) {
    await page.getByRole("button", { name: "Skip", exact: true }).click();
  }
  await expect(page.locator('[aria-current="step"]')).toContainText("High-level design");
  await page.goBack();
  await expect(page).toHaveURL(/\/$/);

  await page.getByRole("link", { name: QUICK_NAME, exact: true }).click();
  await expect(page).toHaveURL(new RegExp(`/design/${QUICK_ID}$`));
  const quickUrl = page.url();

  await page.getByRole("button", { name: "Run", exact: true }).click();
  await expect(page.getByText(/^[\d.]+k? rps$/).first()).toBeVisible({ timeout: 10_000 });
  await page.getByRole("button", { name: "Stop", exact: true }).click();
  await expect(page.getByText("Passed", { exact: true })).toBeVisible({ timeout: 10_000 });
  await expect(page.getByRole("region", { name: "Challenges" })).toBeVisible();

  await page.getByRole("button", { name: "Try a full practice interview", exact: true }).click();
  await expect(page).toHaveURL(DESIGN_URL);
  expect(page.url()).not.toBe(quickUrl);

  // Practice layout, fresh interview: phase 1 with a full clock, canvas locked
  await expect(page.locator('[aria-current="step"]')).toContainText("Requirements");
  await expect(page.getByLabel("Time remaining in current phase")).toHaveText(/^0[45]:\d\d$/);
  await expect(page.getByText(/Canvas unlocks in the High-level design phase/)).toBeVisible();
  // nothing leaked from Quick: no verdict, no run, Practice's default preset, no Quick UI
  await expect(page.getByRole("button", { name: "Run", exact: true })).toBeDisabled();
  await expect(page.getByText("Passed", { exact: true })).toHaveCount(0);
  await expect(page.getByRole("combobox").first()).toHaveValue("black-friday");
  await expect(page.getByRole("button", { name: "More scenarios" })).toHaveCount(0);
  await expect(page.getByRole("region", { name: "Challenges" })).toHaveCount(0);

  // both designs are saved, each with its own mode
  await page.goto("/");
  await expect(row(page, QUICK_NAME).getByText("Quick", { exact: true })).toBeVisible();
  await expect(row(page, "Untitled design").getByText("Practice", { exact: true })).toBeVisible();
});
```

```markdown
## Product modes (M7)

One canvas and one simulation engine, three framings ([[docs/superpowers/specs/2026-11-05-product-modes-design|product modes design]]). Modes are a **shell** concern: engines (`src/lib/**`) never see a mode.

| Mode | What `/design/[id]` renders | Since |
|---|---|---|
| **Quick simulation** | Starter design (Client → App server → SQL database), big Run, simple HUD (served RPS, p95, error %), plain-language verdict, event log, replay. Scenarios behind "More scenarios" (Quick-only list), chaos behind "Break it" (only while running), next-challenge card, "Try a full practice interview". No phases, notes, requirements, canvas lock, review screen or action recording. | M7 |
| **Practice** | The full interview, unchanged from M4–M6: phase bar + timers + canvas lock, phase notes, requirements, scenario + chaos panel, action recording, review screen + self-graded scorecard. | M4 |
| **Interview** | Not built (M11). The landing card says "Coming soon"; a record with this mode opens in the Practice layout with a one-line notice. | M11 |

- **Mode is data.** `DesignRecord.mode: DesignMode` (shell type in `persistence/local.ts`). A missing or unknown value loads as `"practice"`, with no migration. A design's mode is fixed for life: in-place "Import JSON" keeps it, and a landing-page import creates a new design with the file's mode.
- **One route.** `DesignWorkspace` attaches the design, waits until it's attached, then picks the layout from a `Record<DesignMode, Component>` map (`QuickWorkspace`, `PracticeWorkspace`, `InterviewPreviewWorkspace`).
- **Quick data is plain data.** Starter graph: `components/quick/starter.ts`. Starter + challenge scenarios: `QUICK_SCENARIOS` in the scenarios engine, never mixed into `SCENARIO_PRESETS`. Challenges: `QUICK_CHALLENGES` (`scenarios/challenges.ts`). Solved state is per browser: `bp:challenges:solved` (`persistence/challenges.ts`).
- **Store lifecycle.** Entering Quick selects the starter scenario. Leaving it resets the sim and restores Practice's default preset (`leaveQuickMode`). Quick never records actions (`recordInterviewAction` returns early).
- **Moving between modes.** No conversion in v1. Quick's "Try a full practice interview" creates a new blank Practice design (same as the landing Practice card with no name), resets the phase clock, and opens it. The Quick design stays saved.
```
