# T-8.2: Async failures separate from client errors

## Goal

Make `errorRate` mean "requests the client saw fail". Drops count toward it only when they happen on the sync (client) path. Work lost after it was handed to a queue (backlog overflow, overloaded consumers, an overloaded store fed only by consumers) is reported separately as `asyncDroppedRps` on every frame. It also gets a grader advisory. Add an optional NFR `pass.maxLagSec` with a verdict criterion that fails the run when consumer lag goes over budget. The HUD shows max consumer lag whenever the design has async nodes: a "Lag" card in Practice and a "Queue lag" card in Quick.

**Accept (verbatim):** `errorRate` counts only drops on the sync (client) path (today all drops are summed, `engine.ts:422`). Async drops (backlog overflow) are reported separately. New optional NFR `pass.maxLagSec` with a verdict criterion. The HUD shows max consumer lag when the design has async nodes.

**Calls made (logged in Decisions, step 12):**
1. **Client share.** "Sync (client) path" is a per-node, per-tick *fraction*, not a static node set. `clientShare(entry) = 1`. `clientShare(async-category node) = 0`. Any other node gets Σ over in-edges of `flow × (edge.kind === "sync" ? clientShare(source) : 0)`, divided by its total in-edge flow. A node with zero inflow this tick keeps last tick's share (initially 0). The frac then covers backlog it is still draining. A node's drops this tick (`out.dropped` + its `unroutable`) are split `× share` into client and `× (1 − share)` into async. So a DB shared by the app (sync) and the workers (behind a queue) only charges clients for their share of its losses. Queue overflow is always async, and consumers are always async. The approximation: carried-over backlog is attributed by *this* tick's mix. Exact for 0 and 1, which covers every single-origin node.
2. **Where a drop is charged.** Stranded flow on a dead (partitioned) edge is charged by its *source's* share, whatever the edge kind. So partitioning the queue shows as client errors at the app: a producer that can't enqueue fails the request. Only work the queue has *accepted* becomes async.
3. `servedRps = max(0, offered − clientDropped)`, so it is client-facing throughput. Async drops don't reduce it.
4. **Async losses go to an advisory.** They don't fail the run. The advisory text: `Async work lost: N jobs dropped after being queued …`. `maxLagSec` is the failing NFR for async health, and an overflowing backlog typically breaches it anyway.
5. **Lag criterion.** It fails on the first frame where `maxLagSec > pass.maxLagSec`, strictly greater. There's no warmup, because lag starts at 0. Only the first breach is reported. Criterion id is `"lag"`.

4. **`app/src/lib/simulation/engine.ts`**: add an exported pure helper below `propagateTraffic`. Engine tests import it from `engine.ts`. Don't export it from `index.ts`.
   ```ts
   /**
    * Fraction of each node's traffic this tick that is on the client (sync)
    * path (T-8.2). Entry = 1; async-category nodes = 0 (work they accepted is
    * off the client path, and so is everything downstream of them); others =
    * client-carried in-edge flow / total in-edge flow, where only sync edges
    * carry the source's share. Zero-inflow nodes keep `prev` (initially 0):
    * their remaining backlog came from earlier ticks. Every graph node gets
    * an entry.
    */
   export function clientShares(
     graph: DesignGraph,
     prop: PropagationResult,
     prev: ReadonlyMap<string, number>,
   ): Map<string, number> {
     const share = new Map<string, number>();
     const nodeById = new Map(graph.nodes.map((n) => [n.id, n]));
     const inflow = new Map<string, { total: number; client: number }>();
     for (const id of prop.order) {
       const node = nodeById.get(id);
       if (!node) continue;
       let s: number;
       if (getComponentDef(node.kind).category === "async") s = 0;
       else if (id === graph.entryNodeId) s = 1;
       else {
         const acc = inflow.get(id);
         s = acc && acc.total > 0 ? acc.client / acc.total : (prev.get(id) ?? 0);
       }
       share.set(id, s);
       for (const edge of graph.edges) {
         if (edge.source !== id) continue;
         const rps = flowRps(prop.perEdge[edge.id]);
         if (rps === 0) continue;
         const acc = inflow.get(edge.target) ?? { total: 0, client: 0 };
         acc.total += rps;
         if (edge.kind === "sync") acc.client += rps * s;
         inflow.set(edge.target, acc);
       }
     }
     for (const n of graph.nodes) {
       if (!share.has(n.id)) share.set(n.id, prev.get(n.id) ?? 0);
     }
     return share;
   }
   ```
   (Back edges and edges into the entry carry 0 in `perEdge`, so they add nothing. Every in-edge's source comes earlier in `prop.order`.)

6. **`app/src/lib/simulation/verdict.ts`**: add the criterion and the advisor, and register them.
   ```ts
   /** fail on the first frame whose max consumer lag exceeds pass.maxLagSec */
   export const lagCriterion: Criterion = ({ graph, scenario, frames }) => {
     const budget = scenario.pass.maxLagSec;
     if (budget === undefined) return [];
     for (const f of frames) {
       if (f.maxLagSec <= budget) continue;
       let worst = graph.nodes[0]?.label ?? "?";
       let worstLag = -1;
       for (const n of graph.nodes) {
         const lag = f.perNode[n.id]?.lagSec ?? 0;
         if (lag > worstLag) { worstLag = lag; worst = n.label; }
       }
       return [{
         criterion: "lag",
         atSec: f.t,
         detail: `consumer lag ${f.maxLagSec.toFixed(1)}s on "${worst}" over ${budget}s budget at t=${f.t}s`,
       }];
     }
     return [];
   };

   /** work accepted by a queue but never processed — invisible in errorRate */
   export const asyncLossAdvisor: Advisor = ({ frames }) => {
     const lost =
       frames.reduce((sum, f) => sum + f.asyncDroppedRps, 0) / TICKS_PER_SEC;
     if (lost < 1) return [];
     return [
       `Async work lost: ${formatRps(lost)} jobs dropped after being queued (backlog overflow or overloaded consumers) — clients saw no errors, but that work never ran`,
     ];
   };
   ```
   Append `lagCriterion` to `criteria` and `asyncLossAdvisor` to `advisors`, both last. (`formatRps` is the node-models one already imported. `lost < 1` filters float dust.)
