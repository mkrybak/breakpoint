# T-12.5: p95 explains itself

## Goal

The p95 card becomes a button. Clicking or tapping it opens a small popover with the one-line explanation (`P95_HINT`) and the top 3 nodes by their share of p95 in the frame the canvas is showing. That frame is `latestFrame`, which `scrubTo` already repoints during replay. The engine adds an optional per-frame breakdown, `SimFrame.p95ByNode`, built from T-8.7's moment fold. Each node gets its share of the mean plus its share of the 2σ tail, so the entries sum to `p95Ms`. Errors and Lag cards get the same affordance: a dotted label and a click popover with their existing explanation. All native `title`s on HUD cards go away. Users who saved a design before the T-8.7 model landed see a one-time note under the p95 card on their first run, until they dismiss it. The note is stored per browser in localStorage.

**Accept (verbatim):** Clicking the p95 card opens a small popover (works on touch, replaces reliance on the native `title`) with the one-line explanation and the top 3 nodes by contribution to the tail, from T-8.7's moment fold. The first time a user who has saved designs sees the new p95 model, a one-time dismissible note says p95 is now more realistic: tails grow faster as components get busy. Errors and Lag cards get the same dotted-underline hint affordance as p95.

**Calls made (lead, please review):**
1. **Attribution = Euler allocation.** The fold is linear in each node's own moments, so attribution maps can ride alongside it. Node k's part of p95 = `meanShare_k + 2σ × varShare_k / Σ varShare`. For independent terms this is the standard Euler split of σ (σ_k²/σ), and it sums exactly to `mean + 2σ`. Spread terms (a fractional call's `f(1−f)m'²` and an LB mixture's between-branch spread `w(m' − M)²`) go to the **term's target**, meaning the branch whose path differs. Prototyped against the real engine: the sum matches `p95Ms` within 0.02 ms on every frame of `retry-storm.json` × "3× traffic spike" and `twitter.json` × black-friday. Retry storm at t=20 s: p95 2289 ms = Dependency 2279 + App fleet 9.25 + Client 1.01. So the demo's "which node drives the tail" reads clearly.
2. **Shown numbers = ms of p95 plus % of p95**, not a pure σ share. This is what users can add up ("p95 2.3 s: Dependency 2.3 s · 100%"). In M/M/1, σ = mean per node, so the ranking is the same either way.
3. **Values are rounded to 0.01 ms and zero entries are omitted** in the frame. This keeps run-bundle exports small (600 frames × N nodes). The field is absent when nothing is positive (no entry, p95 0). Pre-T-12.5 bundles lack it, so the popover shows only the explanation.
4. **"User who has saved designs"** means localStorage holds a design whose `updatedAt` is before T-8.7's commit (`2026-11-07T07:19:55.000Z`, commit 56262f1), so this user saw the old 1.6× model. The literal reading ("any saved design") would show the note to every new user, because the landing page saves the record on create, and "now more realistic" means nothing to them. Eligibility is read once at HUD mount, before any edit can autosave and bump `updatedAt` (attaching a design is not a save). The note shows while a run is live (status ≠ idle). It dismisses on "Got it", or by opening the p95 popover while the note is visible. Key: `bp:notes:p95-model` = `"dismissed"`.
5. **The Metric `title` prop is removed.** All four titled cards (Errors and Lag in full; Queue lag in simple; plus simple Errors, which had none) become `hint` cards. Copy moves into hud-format constants unchanged. Simple Errors gets the full bar's text.

To make that easy, `useRunControls` now returns `frame` (= `latestFrame`), and `P95Metric` takes `value`/`sub` as props. The breakdown already follows the scrubber because it reads `latestFrame`. T-12.2 also edits `engine.ts` and `tests/engine.test.ts`, but in different regions (event order and breaker lines), so expect only trivial merges.

Add after `p95FromMoments` (exported for tests, **not** re-exported from `index.ts`):
```ts
/**
 * Per-node share of the entry's p95 (T-12.5), a companion to pathMomentsMap:
 * the same reverse-topo pass over the same terms, but each node carries maps
 * id → (mean part, variance part). The fold is linear in nodes' own moments:
 * a term scales its target's mean parts by w·s and variance parts by w·s²
 * (s = m'/m, termMs's scale). A fractional call's f(1−f)m'² and an LB's
 * between-branch w(m'−M)² go to the term's target. At the entry: ms_k =
 * mean_k + 2σ·var_k / Σvar (Euler allocation), so Σ ms_k = mean + 2σ.
 * Rounded to 0.01 ms; zero entries omitted.
 */
export function p95Breakdown(
  graph: DesignGraph,
  prop: PropagationResult,
  outputs: ReadonlyMap<string, NodeModelOutput>,
  moments: ReadonlyMap<string, PathMoments>,
  policies: ReadonlyMap<string, EdgePolicy> = new Map(),
): Record<string, number>
```
Body (prototyped, gives the numbers quoted above; type the parts as `{ mean: Map<string, number>; variance: Map<string, number> }`):
```ts
  const terms = clientPathTerms(graph, prop, outputs, policies);
  const kindById = new Map(graph.nodes.map((n) => [n.id, n.kind]));
  const parts = new Map<string, NodeParts>();
  const add = (m: Map<string, number>, k: string, x: number) =>
    m.set(k, (m.get(k) ?? 0) + x);
  for (let i = prop.order.length - 1; i >= 0; i--) {
    const id = prop.order[i];
    const out = outputs.get(id);
    if (!out) continue;
    const mean = new Map([[id, out.latencyMs]]);
    const variance = new Map([[id, out.latencyVarMs2]]);
    const split = isSplitSource(kindById.get(id));
    const own = terms.get(id) ?? [];
    const charged = own.map((term) => termMs(term, moments.get(term.target)?.meanMs ?? 0));
    const mixMean = split ? own.reduce((sum, term, k) => sum + term.weight * charged[k], 0) : 0;
    own.forEach((term, k) => {
      const w = term.weight;
      const target = moments.get(term.target);
      const child = parts.get(term.target);
      if (w <= 0 || !target || !child) return;
      const m = charged[k];
      const scale = target.meanMs > 0 ? m / target.meanMs : 0;
      for (const [n, x] of child.mean) add(mean, n, w * scale * x);
      for (const [n, x] of child.variance) add(variance, n, w * scale * scale * x);
      const f = w - Math.floor(w);
      add(variance, term.target, split ? w * (m - mixMean) ** 2 : f * (1 - f) * m * m);
    });
    parts.set(id, { mean, variance });
  }
  const entry = parts.get(graph.entryNodeId);
  const at = moments.get(graph.entryNodeId);
  if (!entry || !at) return {};
  let varSum = 0;
  for (const x of entry.variance.values()) varSum += x;
  const tail = P95_SIGMAS * Math.sqrt(at.varianceMs2);
  const result: Record<string, number> = {};
  for (const node of graph.nodes) {
    const ms =
      (entry.mean.get(node.id) ?? 0) +
      (varSum > 0 ? (tail * (entry.variance.get(node.id) ?? 0)) / varSum : 0);
    const rounded = Math.round(ms * 100) / 100;
    if (rounded > 0) result[node.id] = rounded;
  }
  return result;
```

```ts
export const ERRORS_HINT =
  "Requests the client saw fail. Work dropped after it was queued is not counted here.";
export const LAG_HINT =
  "Max consumer lag: how far behind (seconds) the slowest queue's consumers are. Not part of the error rate.";
export const QUEUE_LAG_HINT = "How far behind the queue's workers are, in seconds.";

/** One-time note for users who saved designs under the old 1.6 × mean p95 (T-12.5). */
export const P95_MODEL_NOTE =
  "p95 is now more realistic: tails grow faster as components get busy, so saved designs may show a higher p95 than before.";

export interface P95Contributor {
  id: string;
  label: string;
  /** ms of the frame's p95 this node accounts for */
  ms: number;
  /** ms ÷ p95Ms, 0–1 */
  share: number;
}

/**
 * The frame's top `limit` nodes by their part of p95 (engine p95ByNode),
 * largest first, ties in graph node order (stable sort). [] when the frame
 * has no breakdown (older bundles) or p95Ms ≤ 0; ids not in the graph are skipped.
 */
export function topP95Contributors(
  frame: SimFrame,
  graph: DesignGraph,
  limit = 3,
): P95Contributor[] {
  const by = frame.p95ByNode;
  if (!by || frame.p95Ms <= 0) return [];
  return graph.nodes
    .filter((n) => (by[n.id] ?? 0) > 0)
    .map((n) => ({ id: n.id, label: n.label, ms: by[n.id], share: by[n.id] / frame.p95Ms }))
    .sort((a, b) => b.ms - a.ms)
    .slice(0, limit);
}
```
