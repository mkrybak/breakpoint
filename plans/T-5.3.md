# T-5.3 — Deploy + CI

## Goal

**Accept (verbatim):** CI runs lint+typecheck+tests (incl. golden sim tests) on push; app deployed to a live URL (Vercel or equivalent — stateless, nothing to operate); environment documented in `app/README.md`.

When done: `app/.github/workflows/ci.yml` runs `npm ci` → `lint` → `typecheck` → `test` (which includes the deterministic golden simulation tests) → `build` on every push and pull request, on Node 22 (production's runtime). `app/README.md` is a real project README — prerequisites, scripts, the "no environment variables" note, a CI summary, and a Vercel deploy runbook — replacing the create-next-app boilerplate. The actual push-to-GitHub and Vercel import (which produce the live URL) are **manual, account-bound steps** the user performs, documented in the README; the implementer's deliverable is the workflow file, the README, and the commit.

## Reality vs. spec (read this first)

Step 3 of planning is "write the plan against reality." The reality that shapes every decision here:

- **The git repository root is `app/` itself**, not the vault root. `git rev-parse --show-toplevel` → `.../sys-design/app`. The specs (`01-architecture.md`, …) live one level **up, outside git**. Consequences:
  - The workflow file goes at **`app/.github/workflows/ci.yml`** (which is `.github/workflows/ci.yml` from the repo's own root — where GitHub Actions looks).
  - Vercel's **Root Directory is `./`** (the repo root = this `app/` folder). No subdirectory config, **no `vercel.json`** — Next.js on Vercel is zero-config.
- **There is no git remote yet** (`git remote -v` is empty) and the app is not deployed. So "deployed to a live URL" cannot be produced by the implementer autonomously — it requires the user's GitHub account and Vercel account. The plan makes the CI + docs ready; the deploy itself is a documented user runbook.
- **Next 16 removed `next lint`, and `next build` no longer runs linting** (confirmed in `node_modules/next/dist/docs/01-app/02-guides/upgrading/version-16.md`, line ~1095: *"The `next lint` command has been removed. … `next build` no longer runs linting."*). The project already lints via the ESLint CLI (`eslint.config.mjs` flat config) in the `lint` script. Therefore:
  - **Do not modify `next.config.ts`.** There is no `eslint` key in Next 16's `NextConfig` (only `typescript.ignoreBuildErrors`), so adding an eslint-ignore would be a type error. `next build` only compiles + typechecks — it is deterministic on its own.
  - No double-lint concern from adding `build` to CI.
- **The existing scripts already are the CI gates.** `package.json`: `lint` = `eslint && depcruise src tests scripts`, `typecheck` = `tsc --noEmit`, `test` = `vitest run`, `build` = `next build`. CI just calls them in order. The golden sim tests (`tests/engine.test.ts`, `node-models.test.ts`, `verdict.test.ts`, `sim-cli.test.ts`) run under `npm test` — no separate step.
- **No environment variables exist.** The app is fully client-side and stateless — no DB, no auth, no API keys (see `01-architecture.md` decision 2026-07-12). "Environment documented" = a README section stating there is nothing to configure.

Resolved as: workflow at `app/.github/workflows/ci.yml` (git root is `app/`); README rewritten; **"host config" = zero-config Vercel, so no `vercel.json` file** — the host setup is a dashboard runbook in the README instead, because deploying is account-bound and manual (no remote configured). `next.config.ts` was intentionally left untouched (Next 16 `next build` doesn't lint). ## Steps

### 1. Create `app/.github/workflows/ci.yml`

New file (this path is `.github/workflows/ci.yml` relative to the git repo root, since the repo root is `app/`). Exact contents:

```yaml
name: CI

on:
  push:
  pull_request:

# Cancel superseded runs on the same ref.
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22 # matches Vercel's production runtime
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Lint (ESLint + dependency-cruiser boundaries)
        run: npm run lint

      - name: Typecheck
        run: npm run typecheck

      - name: Test (incl. golden simulation tests)
        run: npm test

      - name: Build
        run: npm run build
```

Notes for the implementer (do not add anything beyond the file above):
- `actions/setup-node`'s `cache: npm` auto-discovers `package-lock.json` at the repo root — no `cache-dependency-path` needed.
- No `working-directory` is needed: the repo root **is** `app/`, so every command runs in the right place.
- Leave the `on:` triggers exactly as written (bare `push:` = all branches; `pull_request:` = all PRs). This satisfies "on push".

## Environment variables

**None.** The app is entirely client-side and stateless — no database, no auth,
no API keys, no secrets. Persistence is `localStorage` plus JSON file
export/import (design bundles and graded reviews). There is nothing to configure
and nothing to operate.

## Continuous integration

`.github/workflows/ci.yml` runs on every push and pull request. On Node 22 — the
same runtime as production — it runs `npm ci`, then `lint`, `typecheck`, `test`
(including the golden simulation tests), and `build`. A green run means the
commit is deployable.

## Deploy (Vercel)

A zero-config Next.js app — no `vercel.json`. Because the git repository root
**is** this `app/` directory, Vercel's Root Directory is simply `./`.

First-time setup (one-time, from the Vercel dashboard):

1. Push this repo's `main` branch to a GitHub repository.
2. On <https://vercel.com/new>, **Import** that GitHub repository.
3. Vercel auto-detects the **Next.js** preset — leave Build Command
   (`next build`), Output, and Install Command at their defaults.
4. **Root Directory:** `./` (the repo root — this `app/` folder).
5. **Environment Variables:** none.
6. Click **Deploy**.

After setup, every push to `main` deploys to production and every pull request
gets a preview URL — no further action. Since there is no server state, there is
nothing to back up, migrate, or operate.

**Live URL:** _add the production URL here after the first deploy._
