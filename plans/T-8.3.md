# T-8.3 — Split vs fan-out (call) edges

## Goal

Today every edge carries `trafficShare` and validation wants every node's outbound shares to sum to 1, which is right for a load balancer's split but wrong for a node that *calls* several dependencies (app → cache ×1 **and** app → queue ×0.2 = 1.2, a false warning). After this task an edge's meaning comes from its **source kind**: an `lb` source makes it a **split edge** (`trafficShare`, sums to 1, `autoShare` as in T-6.1), and every other source makes it a **call edge** (`callsPerRequest`, default 1, fractional or > 1). The propagation math stays the same (both multiply the forwarded flow), so every golden number is unchanged. Persistence migrates legacy files on read, the CLI goes through the same guard, and the edge inspector labels the two kinds differently.

**Accept (verbatim):** LB edges keep `trafficShare` (a split, which must sum to 1). Every other edge is a **call**, with `callsPerRequest` (default 1, may be fractional, e.g. 0.2 = "20% of requests enqueue a job"). The sum-to-1 warning applies only to LB sources. Import maps a legacy non-LB `trafficShare` to `callsPerRequest` (the propagation math is equivalent, since both multiply). `examples/twitter.json` (app → cache 1.0 + app → fanout 0.2) validates clean. The edge inspector labels the two kinds differently.

Calls made in this plan (the lead should review them):
- **Which kinds split comes from the registry, not a hardcoded `=== "lb"`.** New optional `ComponentDef.splitsTraffic?: boolean`, set to `true` on `lb` only, read through `isSplitSource(kind)` (registry). This one helper serves the engine, validation, design-store, persistence and FlowEdge. `api_gateway` stays a call source: route mixes are written as fractional calls (0.3 / 0.7), which give the same propagation.
- **Absent field = 1.** Both `trafficShare` and `callsPerRequest` are optional on the type. The engine and validation read `trafficShare ?? 1` on split edges and `callsPerRequest ?? 1` on call edges. The store always writes a value on new edges (explicit in exports).
- **The engine never reads legacy fields.** A call edge's `trafficShare` is ignored by the sim. The migration is the persistence guard's job (`parseDesignGraph`), and the CLI now parses through it, so legacy `.json` graphs keep working there too.
- **Migrate on read, no rewrite.** `loadDesign`/`listDesigns`/file import/bundle import all go through `parseDesignGraph`. A stored legacy record is rewritten in the new shape only on the next edit's autosave (attach isn't an edit). This mirrors T-7.2's mode handling.
- **Migration rules per edge.** Split edge: keep `trafficShare` and `autoShare`, drop `callsPerRequest`. Call edge: `callsPerRequest = callsPerRequest ?? trafficShare` (omitted if both are absent), and drop `trafficShare` and `autoShare`. An edge whose source id isn't a node counts as a call edge. Type checks run before the split, so a non-boolean `autoShare` or a non-finite number still rejects the file. The guard now **rebuilds** each edge: unknown edge keys are dropped (nodes still pass verbatim).
- **UI copy.** Split editor: "Share" + 0–1 input + auto checkbox (unchanged behaviour). Call editor: "Calls/req" + input min 0, max 100, step 0.1. Idle chips: split `50%` / `50% · auto`, call `×1` / `×0.2`, plus ` · async` on both.
- **For T-8.4/T-8.5:** the new fields sit together on `DesignEdge` after `kind` (`trafficShare?`, `autoShare?`, `callsPerRequest?`). T-8.5 appends `timeoutMs?`/`retries?` after `callsPerRequest` and adds them to `parseEdge`, the `updateEdge` patch `Pick`, and FlowEdge's editor. `edgeMultiplier` (engine.ts) is the one place the sim turns an edge into a number, so T-8.4's `meanPathMs` can branch on `isSplitSource` the same way.

   /**
    * Strict graph guard + edge migration (T-8.3). Nodes pass verbatim (unknown
    * kinds reject). Each edge is rebuilt for its source's kind: split edges (lb)
    * keep trafficShare/autoShare; call edges keep callsPerRequest, and a legacy
    * (pre-M8) call edge's trafficShare becomes its callsPerRequest, which is the
    * same sim math. Fields foreign to the edge's kind are dropped.
    */
   export function parseDesignGraph(value: unknown): DesignGraph | null {
     if (!isRecord(value)) return null;
     const { nodes, edges, entryNodeId } = value;
     if (!Array.isArray(nodes) || !nodes.every(isValidNode)) return null;
     if (!Array.isArray(edges) || typeof entryNodeId !== "string") return null;
     const kindById = new Map(nodes.map((n) => [n.id, n.kind]));
     const parsed: DesignEdge[] = [];
     for (const raw of edges) {
       const edge = parseEdge(raw, kindById);
       if (!edge) return null;
       parsed.push(edge);
     }
     return { nodes, edges: parsed, entryNodeId };
   }

   function parseEdge(
     value: unknown,
     kindById: Map<string, ComponentKind>,
   ): DesignEdge | null {
     if (!isRecord(value)) return null;
     const { id, source, target, kind, trafficShare, autoShare, callsPerRequest } = value;
     if (typeof id !== "string" || typeof source !== "string" || typeof target !== "string") return null;
     if (kind !== "sync" && kind !== "async") return null;
     if (trafficShare !== undefined && !isFiniteNumber(trafficShare)) return null;
     if (callsPerRequest !== undefined && !isFiniteNumber(callsPerRequest)) return null;
     if (autoShare !== undefined && typeof autoShare !== "boolean") return null;
     const base = { id, source, target, kind };
     if (isSplitSource(kindById.get(source))) {
       return {
         ...base,
         ...(trafficShare !== undefined ? { trafficShare } : {}),
         ...(autoShare !== undefined ? { autoShare } : {}),
       };
     }
     const calls = callsPerRequest ?? trafficShare;
     return { ...base, ...(calls !== undefined ? { callsPerRequest: calls } : {}) };
   }
