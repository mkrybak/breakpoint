# T-13.3: Requirements board

## Goal

Replace the Requirements step's placeholder board with the real one: two side-by-side lists, Functional and Non-functional, made of one-line items. Items can be edited inline, reordered by drag or keyboard, and deleted, and Enter or Backspace make the list keyboard-fast. Non-functional is seeded once per design (per session) from the working scenario's NFRs, and seeded items carry a "scenario" tag. The old `nfrNotesTemplate` seeding of the Requirements notes box is removed. The component takes a `readOnly` mode so T-13.6 can render a record's lists on the review screen.

**Accept (verbatim):**
- Functional and Non-functional columns side by side, each a list of one-line items.
- Items can be edited inline, dragged to reorder (keyboard reorder too), and deleted.
- Enter adds a new item below and focuses it. Backspace on an empty item deletes it and focuses the previous one. "+ add requirement" adds an item at the end.
- Non-functional is seeded once per design from the scenario (target load, p95 budget, max error rate, max lag when present, consistency) when it's empty and the design is attached. Seeded items show a "scenario" tag and are otherwise ordinary.
- New designs no longer get the notes template in the notes box. An old design keeps its note untouched and still gets its list seeded (spec, assistant's call).
- Unit test: seeding values match the scenario, and seeding doesn't re-run after the user empties the list in the same session. The planner decides how "once" is tracked.
- Screenshots: fresh design, edited lists.

## Steps

### 1. `app/src/components/boards/requirements.ts` (new, shell, no React)

```ts
import type { Scenario } from "@/lib/core";
import { useDesignStore } from "@/stores/design-store";
import { useScenarioStore } from "@/stores/scenario-store";

/** One line per scenario NFR, same values and wording the old notes template used. */
export function nfrRequirementTexts(scenario: Scenario): string[] {
  const { baseRps, pass } = scenario;
  const errorPct = Math.round(pass.maxErrorRate * 1000) / 10;
  return [
    `Target load: ${baseRps} RPS`,
    `p95 latency budget: ${pass.p95Ms} ms`,
    `Max error rate: ${errorPct}%`,
    ...(pass.maxLagSec !== undefined ? [`Max consumer lag: ${pass.maxLagSec}s`] : []),
    `Consistency: ${pass.consistency === "strong" ? "Strong" : "Eventual"}`,
  ];
}

/** Final index for a drag from `fromIndex` dropped into gap `gapIndex` (0..length, gap i = before item i). */
export function dropIndex(fromIndex: number, gapIndex: number): number {
  return gapIndex > fromIndex ? gapIndex - 1 : gapIndex;
}

/**
 * Seed the attached design's Non-functional list from the working scenario.
 * Once per design (the persisted `nonFunctionalSeeded` flag, T-13.1); only adds
 * items when the list is empty. Returns whether it added items.
 */
export function seedNonFunctionalOnce(designId: string): boolean {
  const s = useDesignStore.getState();
  if (s.designId !== designId || s.designMode === "quick") return false;
  return s.seedNonFunctional(nfrRequirementTexts(useScenarioStore.getState().scenario));
}
```

  ```ts

    const req = focusRequest.current;
    if (req === null) return;
    focusRequest.current = null;
    if (req === "add") { addButton.current?.focus(); return; }
  ```

- Drag state (component state, set only in event handlers): `const [dragId, setDragId] = useState<string | null>(null)` and `const [gap, setGap] = useState<number | null>(null)`.
- `<ol className="mt-2 flex flex-col gap-0.5" onDragOver={…} onDrop={…}>`:

If `to !== from`, set `focusRequest.current = null` and call `moveRequirement(list, dragId, to)`. Then reset `setDragId(null); setGap(null)`.
- Each row `<li key={item.id} className="group relative flex items-center gap-1.5 rounded" onDragOver={(e) => onRowDragOver(e, index)}>`:
  - `onRowDragOver(e, index)`: if `dragId === null` return, which ignores other columns and foreign drags. Call `e.preventDefault(); e.dataTransfer.dropEffect = "move"`. `const r = e.currentTarget.getBoundingClientRect()` and `const next = e.clientY < r.top + r.height / 2 ? index : index + 1`. If `next !== gap`, call `setGap(next)`.
  - Drop indicator: `{gap === index && <span aria-hidden className="pointer-events-none absolute inset-x-0 -top-px h-0.5 rounded bg-sky-500" />}`, and on the last row also `{gap === items.length && index === items.length - 1 && <span … -bottom-px … />}`.

    ```tsx
    <input
      ref={(el) => { if (el) inputs.current.set(item.id, el); return () => { inputs.current.delete(item.id); }; }}
      type="text" value={item.text} placeholder={placeholder} spellCheck={false}
      aria-label={`${title} requirement ${index + 1}`}
      aria-keyshortcuts="Alt+ArrowUp Alt+ArrowDown"
      onChange={(e) => updateRequirement(list, item.id, e.target.value)}
      onKeyDown={(e) => onItemKeyDown(e, item, index)}
      className="min-h-8 min-w-0 flex-1 rounded bg-transparent px-2 py-1 text-sm text-neutral-100 outline-hidden transition-colors duration-150 placeholder:text-neutral-600 hover:bg-neutral-800/60 focus:bg-neutral-800 focus:ring-2 focus:ring-sky-500/40"
    />
    ```
  - `{item.source === "scenario" && <ScenarioTag />}`
  - Delete: `<button type="button" aria-label={`Delete ${title.toLowerCase()} requirement ${index + 1}`} title="Delete" onClick={() => removeRequirement(list, item.id)} className="flex h-8 w-6 shrink-0 items-center justify-center rounded text-neutral-600 hover:text-neutral-200 focus-visible:ring-2 focus-visible:ring-sky-500/40"><X aria-hidden className="h-3.5 w-3.5" /></button>`. It stays visible at all times: low contrast, no hover-only reveal.
- `onItemKeyDown(e, item, index)`. Return early if `e.nativeEvent.isComposing`. Handle the first matching case, and call `e.preventDefault()` in each handled case:
  1. `Enter`: `const id = addRequirement(list, item.id); focusRequest.current = { id };`. Assigning after the call is safe: React batches the re-render until the handler returns, so the layout effect sees the request.
  2. `Backspace` with `item.text === ""` (and no modifier keys): `const prev = items[index - 1] ?? items[index + 1]; focusRequest.current = prev ? { id: prev.id } : "add"; removeRequirement(list, item.id);`
  3. `ArrowUp` with `altKey` and `index > 0`: `focusRequest.current = { id: item.id }; moveRequirement(list, item.id, index - 1);`
  4. `ArrowDown` with `altKey` and `index < items.length - 1`: same, with `index + 1`.
  5. `ArrowUp` or `ArrowDown` with no modifier: if the neighbour `items[index ∓ 1]` exists, focus its input directly (`inputs.current.get(id)?.focus()`, caret at the end). Otherwise do not call `preventDefault`.
- Footer button: `<button ref={addButton} type="button" aria-label={`Add ${title.toLowerCase()} requirement`} onClick={() => { const id = addRequirement(list); focusRequest.current = { id }; }} className="mt-1 self-start rounded px-2 py-1 text-xs text-neutral-500 hover:text-neutral-200 focus-visible:ring-2 focus-visible:ring-sky-500/40">+ add requirement</button>`.
